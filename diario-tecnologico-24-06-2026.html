Spring AI 2.0 GA — o stack Java para IA chegou à maturidade

Em 12 de junho de 2026, o Spring lançou a versão 2.0 em General Availability. Para quem acompanha o ecossistema Java, é um marco comparável ao lançamento do Spring Boot: uma mudança de paradigma que vai levar tempo para ser totalmente absorvida, mas cujas implicações são claras desde agora. A maior mudança estrutural é a incorporação do MCP (Model Context Protocol) ao core do framework. As anotações @McpTool e @McpToolParam não são mais de um módulo opcional — fazem parte do Spring AI Core. Isso significa que integrar ferramentas em agentes Spring virou quase tão simples quanto criar um @RestController, com a mesma familiaridade que o ecossistema Spring já oferece.

O Spring AI 2.0 também consolidou dois protocolos emergentes como abstrações estáveis: o ACP (Agent Client Protocol), que padroniza a comunicação cliente-agente, e o A2A (Agent-to-Agent), que habilita colaboração direta entre agentes. A inclusão nativa de spans Micrometer e métricas OpenTelemetry para interações MCP é outro sinal de que o framework está mirando produção de verdade, não apenas prototipagem. O meu aviso para times Java: não pulem para o 2.0 sem ler a nova API de Advisors e entender o modelo de memória — quem migrar com pressa vai criar débito técnico que vai doer.

Claude Opus 4.8 — Dynamic Workflows e controle de custo em agentes

O Claude Opus 4.8, lançado pela Anthropic em 28 de maio, está completando um mês em produção, e os relatos de quem trabalha com automação de tarefas complexas estão consistentes: o sistema de Dynamic Workflows no Claude Code é genuinamente útil para problemas de grande escala. A ideia é simples na superfície — um agente orquestrador pode disparar dezenas ou centenas de subagentes em paralelo — mas a execução estável disso em escala não é trivial. O Opus 4.8 também introduziu o controle explícito de esforço computacional: o modelo pode ser calibrado para gastar mais ou menos processamento antes de responder, o que tem impacto direto no custo por requisição.

O Fast Mode do Opus 4.8 opera a 2,5× a velocidade da versão anterior, por um terço do preço — o que começa a tornar o modelo viável para fluxos de maior volume onde antes só os modelos menores cabiam no orçamento. O contexto de 1 milhão de tokens por padrão (disponível na API Anthropic, Amazon Bedrock e Vertex AI) continua sendo o diferencial mais concreto para RAG com documentos extensos, análise de codebases grandes ou workflows que precisam manter histórico longo de interações. Para quem ainda está no Opus 4.7, vale avaliar a migração — a Anthropic manteve o mesmo preço base.

Helidon 4.4 + LangChain4j 1.11 — a Oracle entra sério no jogo dos agentes Java

Em abril de 2026, a Oracle lançou o Helidon 4.4, e o ponto mais relevante para o ecossistema Java-IA é a integração aprofundada com o LangChain4j 1.11. Não é só uma atualização de versão: o Helidon 4.4 adiciona dois padrões de execução agentic nativos — workflows programáticos, para orquestrar múltiplos agentes com controle explícito de fluxo, e dynamic agents, um supervisor agent pronto para uso que gerencia subagentes automaticamente. O suporte ao MCP 1.1 também foi atualizado, com compatibilidade com o mecanismo de Elicitation — onde um servidor MCP pode solicitar input estruturado adicional ao cliente durante o processamento de uma requisição, o que abre caminho para diálogos agênticos mais sofisticados.

Para equipes que já operam com Helidon em microserviços sobre Oracle Cloud, esse release elimina uma parte significativa da fricção de adoção de IA. A pergunta deixa de ser "como integro IA no meu stack Oracle?" e passa a ser "qual padrão agentic faz sentido para o meu caso de uso?". O LangChain4j 1.11 suporta mais de 20 providers de LLM e mais de 30 embedding stores — cobertura de cenários enterprise bastante ampla.

EU AI Act — agosto 2026 não é mais distante, é agora

Em 7 de maio de 2026, um acordo político foi alcançado sobre o chamado "AI omnibus" — um conjunto de propostas para simplificar e racionalizar a implementação do Regulamento de IA europeu. A boa notícia é que houve simplificação. A notícia que muita empresa ainda não processou: as regras de transparência do EU AI Act entram em vigor em agosto de 2026. Isso não é o horizonte de 2027 ou 2028 que costuma aparecer nas apresentações de compliance — é em dois meses.

Para empresas que operam em contextos B2B com clientes europeus ou que têm operações na Europa, as obrigações de transparência cobrem uma faixa mais ampla do que os "sistemas de alto risco". Comunicar ao usuário final que está interagindo com um sistema de IA, manter rastreabilidade de decisões automatizadas e ter documentação técnica acessível já são requisitos concretos. Além disso, cada Estado-Membro da UE deve estabelecer pelo menos uma sandbox regulatória de IA a nível nacional até 2 de agosto de 2026 — o que vai gerar movimentação de oportunidade para empresas que quiserem testar soluções num ambiente regulado antes do enforcement completo.

☕ Radar Java + IA

O ecossistema Java para IA está no seu momento mais maduro até agora em 2026. Três abordagens principais competem pelo espaço, com propostas bem distintas:

Spring AI 2.0 GA — o caminho de menor resistência

Para quem já está no ecossistema Spring, o 2.0 é a escolha natural para projetos novos. A API de ChatClient com DSL fluente, advisors configuráveis, MCP como cidadão de primeira classe e integração nativa com Micrometer/OpenTelemetry formam o stack mais completo disponível hoje em Java para IA em produção. O ponto de atenção é a migração: a API de 1.x para 2.0 tem quebras significativas que exigem atenção.

LangChain4j 1.11 — controle granular com cobertura ampla

Escolha sólida para quem quer controle mais granular ou está num stack Oracle/Helidon. Com suporte a mais de 20 providers de LLM e mais de 30 embedding stores, a cobertura de cenários enterprise é a mais ampla disponível em Java. O módulo MCP client está estável, e o módulo STDIO server — recentemente contribuído pela comunidade — abre caminho para criar servidores MCP diretamente em Java sem boilerplate excessivo.

O padrão que estou observando nos times mais avançados

A combinação que tem aparecido nas arquiteturas mais sofisticadas: Spring AI 2.0 para a camada de aplicação e ChatClient, e LangChain4j para componentes RAG mais específicos e tool-calling granular. Não é uma escolha excludente — é composição. Cada framework tem seu ponto forte.

Exemplo prático — Spring AI 2.0 com MCP em produção

Com base no artigo do Java Code Geeks sobre Spring AI 2.0 + MCP, este é o padrão básico de um agente com ferramentas:

// Spring AI 2.0 — Agente com tool calling via MCP
@Service
public class AnalisadorContratosAgent {

    private final ChatClient chatClient;

    AnalisadorContratosAgent(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("""
                Você é um assistente especializado em análise de contratos.
                Use as ferramentas disponíveis para buscar dados antes de responder.
                Sempre cite o número do contrato nas suas análises.
                """)
            .build();
    }

    public String consultar(String pergunta) {
        return chatClient.prompt(pergunta).call().content();
    }
}

@Component
public class ContratoTools {

    private final ContratoRepository repo;

    ContratoTools(ContratoRepository repo) {
        this.repo = repo;
    }

    @McpTool(description = "Busca contratos ativos por cliente")
    public List<String> buscarContratos(
            @McpToolParam(description = "Nome ou CNPJ do cliente") String cliente) {
        return repo.findNumerosAtivos(cliente);
    }

    @McpTool(description = "Retorna o valor total de contratos vigentes")
    public BigDecimal valorTotalVigente(
            @McpToolParam(description = "Ano de vigência") int ano) {
        return repo.sumValorByAno(ano);
    }
}

O ponto de atenção: @McpTool e @McpToolParam são agora do core do Spring AI 2.0, não de um módulo externo. A integração com o bean do Spring acontece automaticamente via injeção de dependência — sem configuração manual de tool registry.
