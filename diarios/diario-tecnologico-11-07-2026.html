GPT-5.6: OpenAI lança Sol, Terra e Luna com novo paradigma de pricing

No dia 9 de julho, a OpenAI colocou a família GPT-5.6 em disponibilidade geral. São três modelos com propósitos distintos: Sol é o flagship para cargas pesadas (pesquisa científica, coding avançado, cibersegurança); Terra é o mid-range com desempenho comparável ao GPT-5.5 por metade do custo; e Luna é o modelo rápido e barato para tarefas de alto volume.

O que me chamou atenção não é só a qualidade dos modelos — é a estrutura de preços. A OpenAI está claramente tentando cobrir todo o espectro de casos de uso enterprise em uma única família, o que simplifica a decisão de qual modelo usar. Para times que hoje rodam GPT-5.5 em produção, migrar para Terra pode representar uma redução de custo de 50% sem perda significativa de qualidade.

Outro detalhe importante: a OpenAI anunciou que Sol será executado em hardware Cerebras (wafer-scale) com até 750 tokens por segundo — cerca de 15 vezes o throughput atual de GPUs. Isso é relevante para aplicações de chat em tempo real e pipelines de processamento em lote onde latência importa.

Anthropic: Fable 5 reativado + Sonnet 5 com janela de preço agressiva

Dois movimentos da Anthropic merecem atenção. Primeiro: no dia 1º de julho, a Anthropic recolocou o Claude Fable 5 em operação após o governo dos EUA revogar a ordem de controle de exportação que havia tirado o modelo do ar em 12 de junho. Quase três semanas de indisponibilidade no flagship mais poderoso do mercado — um episódio que deixou claro o quanto regulação pode impactar diretamente produtos de IA em produção.

Segundo: a Anthropic lançou o Claude Sonnet 5 com precificação de introdução de $2 por milhão de tokens de entrada e $10 por milhão de tokens de saída, válida até 31 de agosto. Após essa data, os valores sobem para $3 / $15 por 1M tokens. O Sonnet 5 entrega desempenho muito próximo ao Opus 4.8 — o que, na prática, torna este o período mais econômico para migrar cargas que hoje usam Opus.

Janela de oportunidade: você tem até 31 de agosto para aproveitar Sonnet 5 a $2/$10 por 1M tokens — um preço excepcionalmente baixo para a qualidade entregue. Se você tem projetos em planejamento que usarão Claude, avalie iniciar agora para capturar essa economia.

No contexto de pricing geral do mercado, o Fable 5 custa $10/$50 por 1M tokens. Ou seja: Sonnet 5 a preço introdutório custa 1/5 do Fable 5 com qualidade comparável ao Opus 4.8. É uma decisão de FinOps óbvia para a maioria dos casos de uso.

Agentic RAG com Knowledge Graphs: 62% menos alucinação, mas o custo de tokens é real

Um benchmark publicado pela comunidade MLOps em maio de 2026, que está repercutindo agora, trouxe um número significativo: sistemas de Agentic RAG com knowledge graphs reduziram alucinações em aproximadamente 62% em 47 deployments de produção. O dado confirma uma hipótese que muitos arquitetos já trabalhavam — conhecimento estruturado em grafos reduz ambiguidade de recuperação e melhora o grounding das respostas.

O contraponto que não pode ser ignorado: esse ganho de qualidade tem preço. O custo de tokens em Agentic RAG é de 3 a 10 vezes maior que em RAG de passagem única, por conta dos múltiplos ciclos de recuperação, reavaliação e reformulação de queries. Para sistemas enterprise onde qualidade de resposta tem valor financeiro direto — diagnóstico médico, jurídico, compliance — esse multiplicador é justificável. Para casos de uso de sumarização ou FAQ, provavelmente não.

Minha posição: Agentic RAG com KG é uma ferramenta de nicho de alto valor — não uma substituição padrão para RAG simples. A decisão precisa ser orientada pelo ROI do caso de uso específico, não por modismo arquitetural.

LangChain4j formaliza módulo agentic com MCP e A2A como submódulos dedicados

No ecossistema Java, a novidade mais relevante da semana é a consolidação formal do módulo langchain4j-agentic na linha 1.x, com submódulos dedicados para integração com Model Context Protocol (langchain4j-agentic-mcp) e comunicação Agent-to-Agent (langchain4j-agentic-a2a). Isso representa uma maturação importante: a orquestração multi-agente deixa de ser um padrão improvisado e passa a ter abstrações de primeira classe na biblioteca.

O submódulo A2A usa DefaultA2AClientBuilder para conectar agentes remotos via HTTP/REST — o que significa que é possível construir arquiteturas distribuídas onde agentes Java se comunicam com agentes em Python, Node.js ou qualquer runtime que exponha o protocolo A2A. Isso é relevante para times que precisam de interoperabilidade entre ecossistemas sem abrir mão da JVM como runtime principal.

LangChain4j 1.x — O que mudou

A divisão formal do módulo agentic em submódulos dedicados é a notícia da semana no mundo Java. A estrutura atual é:

  • langchain4j-agentic: abstrações core para orquestração multi-agente
  • langchain4j-agentic-mcp: integração com Model Context Protocol via McpService
  • langchain4j-agentic-a2a: comunicação Agent-to-Agent via HTTP/REST com DefaultA2AClientBuilder

Essa divisão é uma decisão de design inteligente: permite que times adotem incrementalmente — você pode usar só o core agentic sem puxar a dependência de MCP ou A2A se não precisar. O Maven Repository já lista os artefatos separados.

Spring AI 2.0.0-M2 — Contexto

O milestone M2 do Spring AI 2.0, anunciado em janeiro de 2026 e construído sobre Spring Boot 4, trouxe anotações de null-safety JSpecify em toda a API pública. Isso pode parecer detalhe, mas para times com tooling estático habilitado (Kotlin, NullAway, etc.) é uma mudança relevante em manutenibilidade. O GA do 2.0 ainda não tem data confirmada — monitore o milestone tracker do Spring.

Exemplo prático: agente A2A com LangChain4j

Um padrão que tenho visto ganhar tração para conectar agentes Java a agentes externos via protocolo A2A:

// Dependência no pom.xml
// <dependency>
//   <groupId>dev.langchain4j</groupId>
//   <artifactId>langchain4j-agentic-a2a</artifactId>
//   <version>1.10.x</version>
// </dependency>

import dev.langchain4j.agentic.a2a.DefaultA2AClientBuilder;
import dev.langchain4j.agentic.a2a.A2AAgent;

// Conectar a um agente remoto (pode ser Python, Node.js, etc.)
A2AAgent remoteAgent = DefaultA2AClientBuilder.builder()
    .baseUrl("https://meu-agente-python.internal/a2a")
    .connectTimeout(Duration.ofSeconds(10))
    .readTimeout(Duration.ofSeconds(30))
    .build()
    .toAgent();

// Usar o agente remoto como ferramenta em um AiService Java
@AiServices
public interface PipelineOrchestrator {
    @Tool("Delegar análise de risco para agente especializado")
    String analisarRisco(@P("contexto") String contexto);
}
