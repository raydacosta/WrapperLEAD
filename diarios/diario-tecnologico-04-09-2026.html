🔴 Alta Relevância

Anthropic lança Claude Fable 5.1 e Mythos 5.1 — cache 75% mais barato

A Anthropic lançou em 1º de setembro o Claude Fable 5.1 e seu gêmeo de acesso restrito Mythos 5.1, com um número que eu não consigo ignorar: redução de 75% no preço de leitura de cache, caindo de $1,00 para $0,25 por milhão de tokens. A base de preço de entrada e saída se manteve em $10 e $50 por milhão, respectivamente. No benchmark Terminal-Bench-Science, o modelo atingiu 52,6% — o que não é apenas incremental.

O que isso muda na prática? Para agentes com contexto longo — pense em contratos jurídicos, análise de código de repositórios inteiros, assistentes com histórico acumulado — o custo efetivo cai entre 25% e 45% dependendo da intensidade de cache na carga de trabalho. Nos pipelines que tenho em produção com system prompts pesados e documentos de referência fixos, essa mudança de preço pode representar a diferença entre uma funcionalidade sendo viável ou não para um cliente de médio porte. A Anthropic também ajustou o TTL do cache: 5 minutos (cache-write a $12,50/MTok) e 1 hora ($20/MTok). Vale calibrar qual TTL faz sentido para cada caso de uso — não existe resposta universal.

O Mythos 5.1 é a variante de acesso controlado voltada para cenários de segurança cibernética — seguindo o padrão que OpenAI e Google também adotaram nessa rodada. Ainda não tenho acesso ao gated program, mas vou acompanhar de perto.

OpenAI lança GPT-6 Astra — primeiro modelo a ativar safeguard crítico de cibersegurança

Em 3 de setembro, a OpenAI lançou o GPT-6 Astra — e junto com o lançamento veio uma notícia que merece atenção separada: este é o primeiro modelo da OpenAI a atingir o threshold de capacidade cibernética que aciona seus mecanismos internos de salvaguarda. A empresa confirmou que isso significa que acesso à variante Cyber do modelo é controlado por um programa de defensores — pesquisadores de segurança credenciados e equipes de resposta a incidentes.

Como arquiteto de software, o que me interessa aqui não é o aspecto sensacionalista, mas o que isso sinaliza sobre a trajetória de capacidade dos modelos. Se o GPT-6 Astra está ativando thresholds que modelos anteriores não ativavam, isso significa que a barreira de capacidade para automação de tarefas complexas (incluindo análise de vulnerabilidades, geração de exploits e engenharia reversa) caiu significativamente. Para times de segurança e pentesters, isso é uma ferramenta poderosa. Para quem constrói sistemas enterprise, é um lembrete de que modelos com acesso irrestrito à internet e ferramentas de execução de código precisam de políticas de governança sérias.

Google DeepMind: Gemini 3.8 Flash com variante Cyber para defensores

No dia 2 de setembro, o Google DeepMind entrou na sequência com o Gemini 3.8 Flash, incluindo uma variante Cyber de acesso restrito — o mesmo padrão que Anthropic e OpenAI adotaram. O que me chamou atenção aqui é o claim de desempenho: o Gemini 3.8 Flash afirma superar tanto o Mythos 5 quanto o GPT-5.6 Sol na descoberta autônoma de vulnerabilidades, com nível frontier.

Para equipes enterprise, o Gemini 3.8 Flash tem relevância imediata: é um modelo de latência baixa (Flash), o que significa que ele se encaixa melhor em pipelines de produção com requisitos de tempo de resposta apertados do que modelos maiores. Se a Anthropic domina meu stack pela qualidade de raciocínio do Fable, o Google Flash é o que eu uso quando preciso de throughput alto e custo controlado. Com a nova versão, essa decisão fica ainda mais interessante de calibrar.

Agentic RAG vira padrão de fato — e 40% dos projetos serão cancelados até 2027

Dois dados do Gartner circularam essa semana que valem comentário: primeiro, que 33% dos aplicativos enterprise terão componentes de IA agêntica até 2028. Segundo, que mais de 40% dos projetos de IA agêntica serão cancelados até o final de 2027 por custo escalando sem controle e ausência de frameworks de risco adequados. Isso não é pessimismo — é a realidade de qualquer tecnologia que vai de protótipo a produção sem disciplina de engenharia.

A lição que tiro disso é clara: Agentic RAG não é uma questão de "se vamos adotar", mas de "como vamos operar em produção de forma sustentável". Governança de custo por token, observabilidade de agentes e circuit breakers para loops autônomos não são opcionais — são requisitos arquiteturais de primeira ordem.

Inferência já é o segundo maior custo de IA enterprise — FinOps de tokens virou obrigação

☕ Radar Java + IA

O ecossistema Java com IA está em um ponto de maturidade que me deixa genuinamente satisfeito. O LangChain4j 1.17.2 (julho de 2026) e o Spring AI 2.0 GA (junho de 2026) formam hoje a base mais sólida que já tivemos para construir sistemas RAG e agentes em Java. Ambos suportam MCP (Model Context Protocol), o que significa que ferramentas externas — desde buscas na web até execução de queries SQL — são cidadãos de primeira classe nos seus pipelines de agentes.

Com a redução de cache do Fable 5.1, o ponto de atenção imediato no stack Java é garantir que o SDK da Anthropic está configurado corretamente para aproveitar o prompt caching. No Spring AI 2.0, isso se traduz em configurar o CacheControl adequado nas opções do modelo. Para agentes com system prompts longos — algo muito comum em assistentes jurídicos, de compliance ou de análise de código que construímos aqui — ativar TTL de 1 hora pode reduzir o custo total do pipeline entre 30% e 45%.

O LangChain4j também está evoluindo bem no suporte a RAG agêntico: o padrão de query routing com múltiplos retrievers foi estabilizado nas versões recentes, e a integração com bancos vetoriais como pgvector (via Spring Data) ficou mais direta no contexto do Spring AI 2.0. Para quem está avaliando qual framework usar hoje em projetos novos, minha posição se mantém: Spring AI se você já tem Spring Boot no stack; LangChain4j se precisar de controle granular sem opinião de framework.

Exemplo: Spring AI 2.0 + Claude Fable 5.1 com cache de 1 hora

// Configuração do ChatClient com Claude Fable 5.1 e cache ativo
@Configuration
public class AiConfig {

    @Bean
    public ChatClient chatClient(ChatClient.Builder builder) {
        return builder
            .defaultSystem("""
                Você é um assistente jurídico especializado em contratos enterprise.
                [SYSTEM PROMPT LONGO — este conteúdo fica no cache por 1 hora]
                """)
            .defaultOptions(AnthropicChatOptions.builder()
                .model("claude-fable-5-1-20260901")
                .maxTokens(4096)
                .cacheControl(CacheControl.oneHour()) // TTL 1h: $20/MTok na escrita, $0.25/MTok na leitura
                .build())
            .build();
    }
}

// Uso em produção: múltiplas chamadas reutilizam o cache do system prompt
public String analisarContrato(String clausula) {
    return chatClient.prompt()
        .user(u -> u.text("Analise a seguinte cláusula e identifique riscos: {clausula}")
                    .param("clausula", clausula))
        .call()
        .content();
}

A lógica é simples: você paga $20/MTok na primeira escrita do cache (TTL 1h), mas nas chamadas subsequentes dentro dessa hora paga apenas $0,25/MTok — 80 vezes mais barato. Para um sistema com 500 chamadas por hora com system prompt de 10k tokens, isso representa uma economia expressiva no FinOps mensal.
