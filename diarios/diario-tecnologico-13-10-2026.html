Claude Haiku 5.5: o primeiro modelo com esforço configurável — e 90% mais barato

A Anthropic lançou o Claude Haiku 5.5 em 7 de outubro, e este é o lançamento técnico mais relevante da semana para quem desenvolve aplicações com LLMs. Pela primeira vez em uma família Haiku, é possível configurar o nível de esforço do modelo diretamente na chamada de API: low, medium, high, xhigh e max. Isso traduz em controle granular de custo versus qualidade por tipo de tarefa, algo que faz diferença enorme em arquiteturas com múltiplos agentes rodando em paralelo.

Os números de preço são expressivos: $0,10 por milhão de tokens de entrada e $0,50 por milhão de saída, representando uma queda de 90% em relação ao Haiku 4.5. Na prática, o Anthropic afirma redução média de 75% nos custos para workloads típicas. Nos benchmarks reportados, o modelo atingiu 72,4% no OSWorld 2.1 contra 15,7% do Haiku 4.5 — uma diferença absurda para uma classe de modelos pequenos. Disponível agora em AWS, Google Cloud e Azure.

Minha leitura: o padrão de budget tokens / effort control vai se tornar o novo padrão de FinOps com LLMs. Em vez de escolher entre modelo barato e modelo caro, você vai calibrar o esforço por etapa do pipeline. Para agentes Java com LangChain4j, isso abre um caminho claro de otimização de custo sem sacrificar qualidade nas etapas críticas.

GPT-6 chega para todos os usuários do ChatGPT — com nuances importantes

A OpenAI concluiu o rollout do GPT-6 para todas as faixas de assinatura do ChatGPT entre os dias 7 e 8 de outubro. Usuários pagos (Plus, Go) passam a usar GPT-6 Sol no chat padrão; usuários gratuitos recebem GPT-6 Luna. Sem aumento de preço para os planos Free ($0), Go ($8) e Plus ($20). Na API, GPT-6 Sol e Luna foram lançados em 22 de setembro a metade do preço dos equivalentes GPT-5.6 — relevante para quem ainda não migrou.

O ponto que merece atenção crítica: o plano Pro de $200/mês tem suas cotas cortadas pela metade a partir de 30 de outubro — de 200 mensagens GPT-6 Pro por semana para 100, e uso de trabalho (Work) e Codex caindo de 20x Plus para 10x Plus. Para compensar, a OpenAI oferece 62.500 créditos únicos (válidos até 31/12/2026), além de lançar um novo plano Pro de $500/mês com a cota mais alta e acesso ao Ultrafast. Quem depende do plano $200 para uso intenso de API precisa recalcular o orçamento agora.

Do ponto de vista de arquitetura enterprise, a democratização do GPT-6 Luna para o plano gratuito é interessante para prototipagem rápida, mas o que interessa para produção continua sendo a API com controle de custo. E nesse aspecto, o GPT-6 Sol a 50% do preço do GPT-5.6 é, sim, uma mudança que vale revisar nas suas configurações de modelo.

Spring AI 2.1.0-M1: o ecossistema Java continua avançando sem parar

Em 25 de setembro, o Spring AI lançou o milestone 2.1.0-M1, continuando a série de releases agressivos iniciada com o GA do 2.0.0 em junho deste ano. Para quem ainda não migrou: Spring AI 2.x exige no mínimo Java 17 e está construído sobre Spring Boot 4 e Spring Framework 7. A versão 2.0.1 (agosto) já estabilizou o core; o M1 do 2.1 sinaliza as próximas capacidades planejadas para o GA. Vale acompanhar o changelog para entender o que vem por aí — milestones do Spring raramente chegam sem conteúdo substancial.

Para equipes Spring Boot que ainda operam com o 1.x ou com versões antigas do Java, o sinal está claro: a janela de migração tem data de validade. E para novos projetos, não faz sentido iniciar fora do 2.x hoje.

McKinsey 2026: 40% das grandes empresas já escalaram agentes em produção

O levantamento mais recente do McKinsey confirma o que venho vendo em campo: a adoção de agentes IA em escala corporativa dobrou em doze meses. 40% das grandes organizações relatam ter escalado agentes para pelo menos uma função de negócio — ante 27% no levantamento anterior. Entre empresas menores, o número estacionou em torno de 22%. A lacuna de escala não é mais tecnológica; é organizacional e de governança.

O levantamento também aponta o que está travando a adoção em larga escala: orquestração multi-agente, gestão de estado entre agentes e controles de auditoria. GraphRAG — com grafos de conhecimento como memória compartilhada entre agentes — e o protocolo MCP como padrão de conexão de agentes a ferramentas e dados são citados como as apostas de infraestrutura do momento. Para quem está desenhando arquiteturas enterprise com Java, essas duas tecnologias merecem estar no radar técnico agora.

☕ Radar Java + IA

O ecossistema Java com IA está em um dos momentos mais movimentados da sua história. Dois frameworks lideram o campo e, desta vez, ambos entregaram em outubro.

Spring AI 2.x consolidou-se como o caminho natural para times Spring Boot. Com o GA do 2.0.0 em junho e o M1 do 2.1 em setembro, o framework demonstra cadência de entrega confiável. A exigência de Java 17+ e Spring Boot 4 é o único ponto de atenção para quem ainda opera em stacks legadas — mas não há como fugir: quem quer IA de produção com Spring precisa estar no ecossistema moderno. O milestone 2.1.0-M1 vale análise do changelog para antecipar as direções que virão no GA do 2.1.

LangChain4j 1.20.x continua com ciclos de release de duas a quatro semanas, o que para um framework open-source é velocidade de produto. A novidade mais relevante desta linha é o módulo agentic com interfaces tipadas: você declara agentes como interfaces Java e o framework injeta a implementação, permitindo compor workflows de agentes de forma limpa e testável. Para sistemas Quarkus, Helidon ou plain Java, LangChain4j continua sendo a escolha mais natural que o Spring AI.

Um trecho de como o novo padrão de agente tipado funciona no LangChain4j 1.20.x:

// Definindo um agente tipado como interface
@AiService
public interface AnalisadorDeContratoAgent {

    @SystemMessage("Você é um especialista em análise de contratos jurídicos. " +
                   "Analise o texto e retorne os pontos críticos identificados.")
    List<PontoCritico> analisar(@UserMessage String textoContrato);
}

// Composição em um workflow de múltiplos agentes
@Component
public class WorkflowContratos {

    private final AnalisadorDeContratoAgent analisador;
    private final ResumidorAgent resumidor;

    public RelatorioContrato processar(String contrato) {
        List<PontoCritico> pontos = analisador.analisar(contrato);
        String resumo = resumidor.resumir(contrato, pontos);
        return new RelatorioContrato(pontos, resumo);
    }
}
