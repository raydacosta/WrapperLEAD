MCP 2026-07-28: o protocolo finalmente virou enterprise-ready

A especificação MCP 2026-07-28 foi a mudança estrutural mais importante que o ecossistema de agentes recebeu neste ciclo. A revisão é a maior desde o lançamento do protocolo e resolve dois problemas que tornavam o MCP inviável em produção enterprise: gerenciamento de sessão stateful e autenticação corporativa. Com a nova spec, o núcleo do protocolo é completamente stateless — o handshake de inicialização foi removido. Um servidor MCP remoto que antes precisava de sticky sessions, session store compartilhado e deep packet inspection no gateway agora roda atrás de um load balancer round-robin simples. Isso é a diferença entre um protocolo de laboratório e um protocolo de produção.

O segundo ponto crítico é a extensão Enterprise-Managed Authorisation (EMA), que saiu de experimental para estável. Ela conecta o MCP ao identity provider corporativo via OAuth e OIDC, com Anthropic, Microsoft e Okta já adotando. Com 950+ servidores MCP no diretório e usados por milhões de pessoas por dia, a Anthropic também expandiu suporte a embedded UI, observabilidade e private network tunnels. Para empresas com VPCs privadas — que é a realidade da maioria dos clientes corporativos — esse último ponto é o desbloqueador.

Do ponto de vista do LangChain4j: a biblioteca já integra suporte a MCP e tem recebido correções recentes relacionadas à nova spec (como o fix de ClassCastException em schemas com anyOf). Quem está construindo agentes Java conectados a ferramentas externas via MCP precisa validar a versão do SDK utilizada.

DeepSeek V4 Pro 0813: números impressionantes, verificação independente pendente

A DeepSeek colocou o V4 Pro 0813 em GA no dia 13 de agosto sem blog post, sem changelog e sem press release — um lançamento silencioso que chama atenção pelo que o modelo promete. FinOps para LLMs: custo de inferência ultrapassou infraestrutura cloud

O relatório State of FinOps 2026 da FinOps Foundation registrou que 98% das organizações já gerenciam ativamente o gasto com IA — contra apenas 31% dois anos atrás. Mais relevante ainda: o custo de inferência se tornou a segunda maior linha de orçamento em IA corporativa, atrás apenas de pessoal. O gasto enterprise em LLMs APIs passou de US$ 8,4 bilhões em 2025 e está no caminho de dobrar novamente.

O paradoxo que os dados revelam é claro: o preço por token caiu até 280 vezes desde 2022, mas as faturas das empresas continuam subindo. O motivo é arquitetural — workflows agenticos consomem de 5 a 30 vezes mais tokens por tarefa do que um chatbot simples. Quem projetou custos com base em uso conversacional e migrou para agentes com loops de raciocínio, múltiplas chamadas de ferramenta e reranking de RAG levou um choque de orçamento. As estratégias que realmente cortam custos em 30-60%: prompt compression, model tiering, output caching e model routing inteligente. Isso precisa estar na arquitetura, não como afterthought.

Agentic RAG: Pipeline de 6 Camadas (2026)

O RAG moderno vai muito além de retrieve + generate. O padrão 2026 inclui planner, multi-hop retrieval, query rewriting, hybrid search, reranking e graph RAG. Com o MCP novo, o retriever pode agora se conectar a qualquer fonte via protocolo padronizado. Estude a arquitetura completa antes de iniciar qualquer novo projeto RAG.

💰

FinOps para LLMs: Model Routing e Caching

Com workflows agenticos queimando 5-30x mais tokens que chatbots, é imperativo projetar custo no nível arquitetural. Estude prompt caching (Anthropic e Google já suportam), model tiering (usar modelos menores para subtarefas simples) e token budget control em loops de agentes. O break-even para self-hosting começa em ~500k tokens/dia.

MCP Enterprise-Managed Auth (EMA)

A extensão EMA do MCP 2026-07-28 já está estável e é adotada por Anthropic, Microsoft e Okta. Se você está construindo ou arquitetando agentes corporativos que precisam de acesso controlado a ferramentas, esta extensão é o mecanismo correto. Leia a spec oficial antes de implementar auth de MCP do zero.

☕ Radar Java + IA

Esta semana, o ecossistema Java com IA consolidou o que já estava em movimento desde o início do ano. O LangChain4j está na faixa 1.10.x e recebeu correções importantes na integração MCP — especificamente um fix de ClassCastException quando o inputSchema de uma ferramenta MCP contém anyOf junto com type: "object". Quem está usando MCP com servidores que retornam schemas polimórficos (como o do GitHub ou do Google Drive) pode estar vulnerável a essa falha se não estiver na versão mais recente.

O suporte a A2A (Agent-to-Agent) transport está recebendo melhorias de configuração. Este é o mecanismo que permite que agentes Java se comuniquem entre si em uma orquestração multi-agente — exatamente o padrão que uso nos projetos de orquestração da Wrapper Sistemas. A configuração de transport agora é mais flexível, permitindo ajuste de timeouts e estratégias de retry no nível do agente individual. O módulo langchain4j-agentic com sub-módulos para MCP, A2A e padrões comuns agenticos é o lugar certo para quem quer construir agentes robustos em Java.

O Spring AI 2.0.0-M2, anunciado em janeiro e construído sobre Spring Boot 4, segue em maturação. Para projetos novos que já usam o ecossistema Spring, ele é candidato natural. Para projetos standalone sem Spring no stack, o LangChain4j continua sendo a escolha mais enxuta. Ambos suportam o novo MCP 2026-07-28 — a diferença está no nível de abstração e na estrutura de configuração.

Em termos de FinOps para Java: a integração de prompt caching nas principais bibliotecas ainda é manual — você precisa estruturar as chamadas com cache_control explícito na API da Anthropic, por exemplo. Não há ainda uma abstração de alto nível no LangChain4j que gerencie cache automaticamente. Isso é um gap que pretendo endereçar em um dos projetos internos da Wrapper Sistemas nas próximas semanas.

// LangChain4j 1.10.x — Configurando MCP com transport A2A
// Exemplo de configuração de McpToolProvider com novo transport

McpTransport transport = new HttpMcpTransport.Builder()
    .sseUrl("https://seu-servidor-mcp.exemplo.com/sse")
    .timeout(Duration.ofSeconds(30))
    .logRequests(true)
    .logResponses(true)
    .build();

McpClient mcpClient = new DefaultMcpClient.Builder()
    .transport(transport)
    .build();

McpToolProvider toolProvider = McpToolProvider.builder()
    .mcpClients(List.of(mcpClient))
    .build();

// Agente com ferramentas via MCP (nova spec stateless 2026-07-28)
AiServices.builder(MeuAgenteIA.class)
    .chatLanguageModel(chatModel)
    .toolProvider(toolProvider)
    .build();
