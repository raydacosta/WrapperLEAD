GPT-5.6 Luna com queda de 80% no preço — a virada do FinOps para LLMs

Em 30 de julho de 2026, a OpenAI cortou o preço do GPT-5.6 Luna em 80% e do Terra em 20%. Para quem está rodando LLMs em produção com volume significativo, isso não é notícia de benchmark — é uma mudança de planilha. Casos de uso que eram economicamente inviáveis (classificação em lote, sumarização de documentos longos, triagem de suporte) agora precisam ser reavaliados com os novos números.

A família GPT-5.6 (Sol, Terra, Luna) ficou disponível para o público geral em 9 de julho. O Sol é o modelo topo de linha, com resultados de ponta em coding, cybersecurity e ciência. O Terra equilibra capacidade e custo. O Luna é o modelo de custo mínimo — e com 80% de desconto, a relação custo-benefício mudou radicalmente. Minha leitura: as equipes que construíram pipelines sobre GPT-4o ou GPT-5 devem fazer benchmarks urgentes para avaliar a migração para Luna em tarefas que não exigem o topo da fronteira.

Além disso, a OpenAI lançou o Ultrafast em parceria com a Cerebras — uma camada de API que pode atingir até 750 tokens por segundo no Sol, chegando a 14 vezes mais rápido que o ritmo normal do modelo. Para aplicações onde latência é crítica (agentes interativos, automações em tempo real), isso muda o desenho da arquitetura.

EU AI Act Anexo III em vigor — compliance é obrigação, não diferencial

Em 2 de agosto de 2026, as obrigações do Anexo III do EU AI Act entraram em vigor. Isso afeta qualquer sistema classificado como IA de alto risco que opere ou processe dados de cidadãos europeus. As exigências incluem transparência, documentação técnica, supervisão humana e gestão de riscos — e não são requisitos abstratos: precisam estar evidenciados e auditáveis.

O problema que estou vendo no mercado: 88% das organizações já usam IA em ao menos uma função de negócio, mas menos de um terço conseguiu escalar de verdade com maturidade de governança. A maioria está em modo de experimentação ou piloto, sem o arcabouço de compliance necessário para operar sistemas de alto risco com segurança jurídica. Para empresas que atendem o mercado europeu, isso não é mais uma questão de roadmap — é uma questão de risco operacional imediato.

Minha recomendação prática: mapeie hoje quais sistemas da sua organização se enquadram no Anexo III. Documente os modelos utilizados, as decisões que automatizam e os mecanismos de supervisão humana existentes. O mercado de governança de IA está projetado para crescer de USD 2,55 bilhões em 2026 para USD 11 bilhões em 2036 — e quem não construir essa estrutura agora vai correr contra o relógio.

O foco agora está em como usar bem esse contexto — não apenas em encaixar mais texto, mas em estruturar o prompt para aproveitar o que o modelo realmente retém e raciocina bem nessa escala.

☕ Radar Java + IA

O ecossistema Java para IA está em um ponto de maturidade que eu não esperava ver tão rápido. Dois frameworks de produção consolidados, ciclos de release mensais e uma base de adoção enterprise crescendo em ritmo acelerado.

Spring AI 2.0 — a virada para Spring Boot 4

Spring AI 2.0, lançado em junho de 2026, marca a migração oficial para o ecossistema Spring Boot 4. A linha 1.1.x permanece com suporte para Spring Boot 3.5, então não há urgência de migração forçada — mas o novo desenvolvimento da plataforma está concentrado no 2.0. Para quem está iniciando novos projetos, já não tem motivo para começar no 1.1.x. As mudanças mais relevantes incluem anotações completas de null-safety com JSpecify e integração nativa com Model Context Protocol (MCP) — o que simplifica consideravelmente a construção de agentes que precisam invocar ferramentas externas.

LangChain4j 1.10.x — ritmo de release que impressiona

O LangChain4j está na versão 1.10.x com releases mensais desde a estabilização do 1.0 GA em maio de 2025. O ecossistema amadureceu: guardrails de input/output chegaram no 1.1.0, a extensão Quarkus para Azure OpenAI está em 1.1.1, e a adoção enterprise está crescendo em times que preferem uma abordagem mais explícita e menos autoconfigurada do que o Spring AI oferece. Minha avaliação atual: para times Spring-first, o Spring AI 2.0 é o caminho natural. Para times Quarkus ou que precisam de controle mais fino sobre o pipeline de chamada, o LangChain4j ainda é a melhor opção.

Exemplo prático — um pipeline de RAG com Spring AI 2.0 e integração via MCP:

@Service
public class DocumentAnalysisService {

    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    public DocumentAnalysisService(ChatClient.Builder builder,
                                   VectorStore vectorStore) {
        this.chatClient = builder
            .defaultSystem("Você é um assistente especializado em análise de documentos enterprise.")
            .build();
        this.vectorStore = vectorStore;
    }

    public String analyzeWithContext(String query) {
        // Busca documentos relevantes no vector store
        List<Document> relevantDocs = vectorStore.similaritySearch(
            SearchRequest.query(query).withTopK(5)
        );

        // Constrói o contexto RAG e envia ao modelo
        return chatClient.prompt()
            .user(u -> u.text(query))
            .advisors(new QuestionAnswerAdvisor(vectorStore,
                SearchRequest.defaults()))
            .call()
            .content();
    }
}

A interface QuestionAnswerAdvisor do Spring AI 2.0 encapsula o padrão RAG de forma que o código de negócio fica limpo — sem misturar lógica de retrieval com lógica de apresentação. Para quem vem de implementações manuais de RAG, a diferença de manutenibilidade é imediata.

Um ponto que merece atenção no contexto do EU AI Act: se você usa Spring AI em sistemas classificados como alto risco, ative logging estruturado de todas as chamadas aos modelos — input, output, modelo utilizado, versão e timestamp. O framework suporta isso via interceptors customizados no ChatClient. Não é opcional para compliance com o Anexo III.
