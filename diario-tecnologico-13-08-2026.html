EU AI Act: o prazo de 2 de agosto chegou — e 78% das organizações não estavam prontas

Já passou. O prazo de conformidade para sistemas de IA de alto risco sob o EU AI Act entrou em vigor no dia 2 de agosto de 2026. A partir dessa data, quem desenvolve ou implanta IA em áreas como recrutamento, serviços financeiros, saúde, educação e infraestrutura crítica precisa demonstrar conformidade com os Artigos 9 a 17 do regulamento — ou enfrentar multas de até €15 milhões ou 3% do faturamento global anual.

O dado que me preocupa: uma pesquisa de abril de 2026 apontava que 78% das organizações ainda não haviam dado passos concretos em direção à conformidade. Quarenta por cento dos sistemas de IA implantados não tinham sequer uma classificação de risco definida. Isso em um cenário onde o custo estimado de conformidade para grandes empresas varia entre $8 e $15 milhões. Há um risco real de que muitas equipes continuem operando em modo "espera e vê" achando que o Parlamento Europeu vai adiar novamente — e essa aposta pode sair cara.

Para quem constrói com Java e Jakarta EE no enterprise, a mensagem é direta: se o seu sistema envolve tomada de decisão automatizada com impacto em pessoas em qualquer das categorias do Anexo III, a auditoria de conformidade não pode esperar mais. O caminho mínimo exige documentação de risco, rastreabilidade de dados de treino e mecanismos de supervisão humana — tudo isso auditável.

MCP 2026-07-28: a maior reescrita do protocolo — o que quebra e como migrar

A especificação final do Model Context Protocol versão 2026-07-28 foi publicada em 28 de julho e já está sendo adotada pelos clientes principais, incluindo Claude. Esta não é uma atualização incremental — é uma reescrita arquitetural que remove sessões com estado, elimina o handshake de inicialização e reescreve completamente o modelo de autorização. Em termos práticos: implementações de MCP Server construídas antes de julho provavelmente precisam de refatoração.

Os pontos de ruptura mais relevantes para quem desenvolve: o protocolo passa a ter um núcleo stateless, o que simplifica horizontalmente servidores, mas invalida qualquer lógica que dependia de estado de sessão. A autenticação agora alinha ao OAuth 2.1 e OpenID Connect de forma formal — MCP Servers são tratados como OAuth Resource Servers. O registro dinâmico de clientes foi depreciado em favor de Client ID Metadata Documents. Para aplicações desktop e CLI, o problema de redirecionamento para localhost finalmente foi endereçado via `application_type` no registro de cliente.

A boa notícia é que o ecosistema Java já tem suporte via LangChain4j, que atua como MCP Client com transporte WebSocket e HTTP. O trabalho de migração está em entender quais das suas integrações dependem das extensões depreciadas. Sugiro ler o guia de migração oficial antes de atualizar qualquer dependência em produção.

Anthropic embute marcas d'água invisíveis nos textos do Claude — globalmente

A Anthropic anunciou que vai incorporar watermarks invisíveis em textos gerados pelo Claude, inicialmente como resposta às obrigações do EU AI Act, mas com aplicação mundial. A marca d'água não altera o sentido ou a legibilidade do texto, viaja junto quando o conteúdo é copiado e colado e, segundo a empresa, "pode persistir através de algumas edições".

Para times de produto que usam Claude via API e apresentam conteúdo gerado a usuários finais, vale verificar se isso afeta contratos de SLA, políticas de uso ou requisitos de disclosure existentes. Para o enterprise, a rastreabilidade é um benefício — para produtos onde a IA é invisível na experiência do usuário, pode abrir questões de política que precisam de resposta jurídica.

☕ Radar Java + IA

O ecossistema Java para IA chegou em 2026 a um ponto de maturidade que não exige mais justificativa. LangChain4j está na versão 1.10.x com releases mensais consistentes desde a estabilização da 1.0 em maio de 2025. Spring AI saiu da 1.1 (novembro de 2025, com integração MCP completa e mais de 20 backends de modelo) e agora avança em direção ao 2.0, construído sobre Spring Boot 4. Ambos suportam MCP como cliente — e a pergunta deixou de ser "dá pra fazer em Java?" para "qual é a arquitetura certa para o meu caso?"

Com a nova spec MCP 2026-07-28, o módulo langchain4j-agentic ganha relevância ainda maior. Ele consolida em um único artefato o suporte a MCP Client, Agent-to-Agent (A2A) e padrões de orquestração que antes precisavam de wiring manual. O transporte WebSocket via HttpClient nativo do Java e o transporte HTTP são os dois modos suportados. Para quem está migrando de versões pré-julho, o ponto de atenção é garantir que o servidor MCP que você consome também foi atualizado para a nova spec — caso contrário, o cliente novo pode não negociar corretamente com o servidor antigo.

No campo de RAG, o padrão que está dominando em produção é o Agentic RAG — agentes especializados de recuperação por domínio de conhecimento, com um orquestrador que roteia queries com base em classificação de intenção. Organizações que adotaram RAG reportam 60-80% menos alucinações e 3x mais acurácia em queries de domínio específico em relação a modelos base. Para cenários enterprise com EU AI Act, o caminho obrigatório passa por Permission-Aware RAG — recuperação que respeita controles de acesso por documento, essencial para conformidade com os artigos de transparência e governança da nova regulação europeia.

Exemplo: MCP Client com LangChain4j 1.x

// LangChain4j 1.x — Conectando a um MCP Server via HTTP (spec 2026-07-28)
import dev.langchain4j.mcp.client.DefaultMcpClient;
import dev.langchain4j.mcp.client.transport.http.HttpMcpTransport;

HttpMcpTransport transport = HttpMcpTransport.builder()
    .sseUrl("https://meu-servidor-mcp/sse")
    .logRequests(true)
    .logResponses(true)
    .build();

McpClient mcpClient = new DefaultMcpClient.Builder()
    .transport(transport)
    .build();

// As ferramentas do servidor MCP ficam disponíveis como ToolSpecification
// e podem ser passadas diretamente ao ChatLanguageModel
List<ToolSpecification> tools = mcpClient.listTools();

A migração para o novo spec exige revisar como a autenticação é negociada no transporte. Com OAuth 2.1, o servidor agora precisa responder com os metadados de Resource Server corretos. Se você tem MCP Servers Java em produção, verifique a cadeia de autorização antes de atualizar o cliente.
