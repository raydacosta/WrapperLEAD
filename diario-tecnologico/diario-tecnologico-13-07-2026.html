GPT-5.6 Sol Ultra prova conjectura matemática de 50 anos com 64 subagentes em menos de 1 hora

Em 10 de julho, a OpenAI anunciou que o GPT-5.6 Sol Ultra produziu uma prova da Cycle Double Cover Conjecture — uma conjectura em teoria dos grafos proposta independentemente por Szekeres (1973) e Seymour (1979) e que resistiu por cerca de 50 anos a tentativas de prova formal. O resultado foi obtido em menos de uma hora usando um sistema de 64 subagentes paralelos.

O que me interessa aqui não é o resultado matemático em si — que ainda está sendo verificado por matemáticos antes de qualquer peer review formal. O que me interessa é o design do sistema. O prompt, publicado pela OpenAI, instrui o modelo a gerenciar os subagentes "de forma agressiva e dinâmica", sem papéis fixos. Nas primeiras rodadas, os agentes mantêm diversidade intencional — cada um perseguindo formulações matemáticas distintas, ângulos algébricos diferentes e induções estruturais independentes. Agentes adversariais são designados especificamente para caçar edge cases e erros nos trabalhos dos outros agentes.

Isso é exatamente o padrão que eu venho defendendo em projetos enterprise: diversidade de perspectiva nos subagentes + verificação adversarial é mais robusto do que N agentes idênticos fazendo a mesma coisa. A abordagem reduz a conjectura a grafos cúbicos, usa o teorema de 8-fluxos e constrói uma rotulagem de arestas. O que importa para nós: a arquitetura de orquestração é replicável em qualquer domínio com alta complexidade — jurídico, compliance, análise de código, engenharia de dados.

Claude Sonnet 5: preço introductório de US$ 2/US$ 10 por milhão de tokens até 31 de agosto

Lançado em 30 de junho, o Claude Sonnet 5 já está como modelo padrão nos planos Free e Pro da Anthropic, e disponível via API nos planos pagos. O ponto central: performance próxima ao Opus 4.8 a um preço introductório de $2 por milhão de tokens de entrada e $10 de saída — válido até 31 de agosto. Após essa data, o preço passa para $3/$15. Comparando com o Sonnet 4.6, que eu uso extensamente nos meus projetos, a relação custo-benefício para pipelines agentivos melhorou substancialmente.

Os detalhes técnicos que me importam: contexto de 1 milhão de tokens por padrão, saída máxima de 128k tokens, e um tokenizador novo que gera aproximadamente 30% mais tokens para o mesmo texto — o que significa que prompts migrados do Sonnet 4.6 vão custar mais por execução, então é necessário revisar e comprimir antes de migrar cegamente. A Anthropic também reporta melhora em raciocínio, uso de ferramentas, código e trabalho de conhecimento — todas as dimensões relevantes para agentes.

O ponto de economia real está no prompt caching: até 90% de redução de custo com caching e 50% com batch processing. Para pipelines de RAG enterprise com prompts de sistema estáveis e alto volume de requisições, isso muda a matemática de viabilidade financeira do produto.

EU AI Act: prazo de agosto 2026 se aproxima com 78% das organizações fora de conformidade

Em 2 de agosto de 2026, o EU AI Act entra na sua fase de aplicação mais abrangente para sistemas de IA de alto risco e modelos de IA de propósito geral (GPAI). O que estava sendo tratado como "ainda vai chegar" chegou. O dado que me preocupa: 78% das organizações ainda não tomaram medidas significativas em direção à conformidade até meados de 2026, segundo levantamentos setoriais.

Os custos são reais: conformidade para um único sistema de IA de alto risco pode custar aproximadamente €52.000 por ano. Para grandes empresas, o custo de primeiro ano está estimado entre €8 milhões e €15 milhões, cobrindo avaliações de conformidade, documentação, sistemas de gestão de risco e monitoramento contínuo. As multas chegam a €35 milhões ou 7% do faturamento global anual — superando o teto do GDPR.

Para quem constrói soluções enterprise com LLMs, o impacto é imediato: rastreamento de GPU hours, logging detalhado de chamadas a modelos, documentação de risco e avaliações de conformidade deixam de ser boas práticas e passam a ser requisitos legais. Se você está entregando sistemas classificados como alto risco para clientes europeus — ou construindo GPAI — agosto é uma data que não pode ser ignorada. Minha recomendação: começar pelo inventário de sistemas agora.

MCP agora é nativo em todos os 7 principais frameworks de agentes — e CrewAI entrega atualização substancial

Q2 de 2026 foi o trimestre mais movimentado para o ecossistema de frameworks de agentes. O dado mais significativo: todos os 7 principais frameworks agora embarcam suporte nativo ao Model Context Protocol (MCP), refletindo uma padronização que estava sendo esperada há algum tempo. Isso simplifica muito a integração de ferramentas externas em pipelines agentivos.

O destaque do período foi a release de 11 de junho do CrewAI, que adicionou backends plugáveis para memória, conhecimento, RAG e fluxo — além de uma Chat API para fluxos conversacionais, um provider nativo para Snowflake Cortex, e gerenciamento de estado com escopo de execução. Para quem usa CrewAI em projetos de dados enterprise, o suporte a Snowflake Cortex é especialmente relevante para integrar LLMs diretamente no data warehouse sem sair do ecossistema.

LangChain4j 1.15.0 — módulo agentic com MCP e A2A

A principal mudança arquitetural da série 1.x do LangChain4j foi a formalização de um módulo dedicado para capacidades agentivas: o langchain4j-agentic. Ele organiza sub-módulos para MCP (Model Context Protocol), A2A (Agent-to-Agent) e padrões agentivos comuns — saindo do modelo de "classe monolítica" que víamos antes. Para quem está migrando agentes criados com versões 0.x, o passo mais importante é separar a lógica de orquestração do acesso a ferramentas e reestruturar usando os contratos do módulo agentic.

Spring AI 2.0.0-M2 — o caminho para GA

O milestone 2 do Spring AI 2.0 foi anunciado em janeiro de 2026 com base no Spring Boot 4. A integração full com MCP já está disponível desde a versão 1.1, e a Advisors API estruturada facilita a composição de comportamentos em pipelines de RAG. Para times que vivem no universo Spring, este é o caminho natural — mas para quem precisa de mais flexibilidade de provider ou padrões agentivos avançados, o LangChain4j ainda tem vantagem.

LangGraph4j — grafos de estado para agentes Java

Merece atenção o projeto LangGraph4j, que traz a abordagem de grafos de estado do LangGraph para o ecossistema JVM — compatível tanto com LangChain4j quanto com Spring AI. Para pipelines agentivos com controle de fluxo explícito (condicional, paralelo, loop com estado), essa abstração é mais expressiva que um agente linear simples. Vale monitorar os releases.

Exemplo: estrutura básica com langchain4j-agentic e MCP

// Dependência Maven — langchain4j-agentic 1.15.0
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-agentic</artifactId>
    <version>1.15.0</version>
</dependency>

// Definindo um agente com suporte a MCP
ChatLanguageModel model = AnthropicChatModel.builder()
    .apiKey(System.getenv("ANTHROPIC_API_KEY"))
    .modelName("claude-sonnet-5-20260630")
    .build();

McpToolProvider mcpTools = McpToolProvider.builder()
    .mcpClients(List.of(mcpClient))
    .build();

Agent agent = Agent.builder()
    .chatLanguageModel(model)
    .toolProvider(mcpTools)
    .build();

AgentResponse response = agent.chat("Analise o contrato e extraia as cláusulas de rescisão.");

O ponto prático: com o Sonnet 5 no lugar do Sonnet 4.6, pipelines agentivos Java via LangChain4j ficam economicamente mais viáveis para execuções longas — especialmente quando o prompt do sistema é estável e pode ser cacheado. Reveja a configuração de caching na sua instância da API antes da migração de modelo.
