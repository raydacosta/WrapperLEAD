🔥 O que chamou minha atenção neste mês

🔴 Alta Relevância

Claude Fable 5.1 e Mythos 5.1: o melhor modelo da Anthropic com 75% de desconto em cache

No dia 2 de setembro, a Anthropic lançou o Claude Fable 5.1 e o Claude Mythos 5.1 — basicamente o mesmo modelo base com duas camadas de acesso distintas. O Fable 5.1 está disponível para todos via API, Claude Code, Cursor e plataforma Claude. O Mythos 5.1 é uma versão de acesso restrito para organizações vetadas em cibersegurança e ciências da vida, com contexto de 1 milhão de tokens e capacidades mais agressivas de análise.

O que realmente importa aqui não é só a melhora de performance — que existe e é mensurável especialmente em tarefas de raciocínio de alta complexidade — mas o corte de 75% no preço de leitura de cache. O token cacheado de entrada caiu de $1,00 para $0,25 por milhão. Mantendo o input padrão em $10/M e output em $50/M. Para aplicações que dependem muito de prompts longos repetitivos — como sistemas RAG com contexto fixo de instruções — isso muda substancialmente o FinOps do projeto. Na prática, se o seu sistema já usa prompt caching bem implementado com Fable 5, você pode revisitar sua planilha de custo e ver uma redução real de 20% a 40% no total dependendo do padrão de uso.

Minha leitura: a Anthropic está apostando que, ao baratear o custo de sistemas de agentes com contexto longo, vai dominar o mercado enterprise antes que a OpenAI ou Google reajam. E com o Mythos 5.1 como produto diferenciado para segurança e pesquisa, eles estão criando um moat em verticais de alto valor regulatório.

🔴 Alta Relevância

OpenAI lança GPT-6 Sol e Luna: a reestruturação da família GPT-6 com corte de preços de 50%

Em 22 de setembro, a OpenAI formalizou dois novos membros da família GPT-6: o GPT-6 Sol, voltado para tarefas de codificação complexa e workflows agentic, e o GPT-6 Luna, o modelo mais eficiente da linha para tarefas de alto volume e baixa latência. Ambos foram treinados com as mesmas metodologias do GPT-6 Astra, mas otimizados para velocidade e custo.

Modelo Input (por M tokens) Output (por M tokens) Foco
GPT-6 Sol $2,00 $10,00 Codificação, agentes, raciocínio
GPT-6 Luna $0,10 $0,50 Alto volume, tarefas focadas

O Luna a $0,10/M de input é o número que me interessa mais. Isso coloca a OpenAI competindo diretamente com provedores de inference dedicados em termos de custo por token. Para pipelines de extração, classificação ou sumarização em escala — onde você roda milhares de chamadas por hora — essa faixa de preço transforma a viabilidade de projetos que antes teriam FinOps proibitivo. O Sol, por outro lado, posiciona bem a OpenAI no segmento de agentes de codificação onde Claude Fable 5.1 era virtualmente imbatível.

Paralelamente, a OpenAI abriu sua Agents API para todos os desenvolvedores — antes em acesso restrito. A API combina sessões duráveis, uso de ferramentas, orquestração de subagentes e suporte a ambientes de execução externos. Quem ainda não testou o loop de agente nativo da OpenAI vai encontrar uma arquitetura bastante madura.

🟡 Média Relevância

Google Gemini 3.8 Flash: terceiro Flash em seis semanas, agora com variante Cyber

Também em 2 de setembro — o mesmo dia do lançamento da Anthropic — o Google DeepMind anunciou o Gemini 3.8 Flash, descrito internamente como o melhor modelo de raciocínio e programação da geração Flash até agora. Este é o terceiro lançamento da linha Flash em apenas seis semanas, o que demonstra um ritmo de iteração que está começando a ser difícil de acompanhar até para quem vive disso.

O 3.8 Flash traz melhorias explícitas em engenharia de software e fluxos agentic autônomos. A variante Gemini 3.8 Flash Cyber, lançada em conjunto, é especializada em descoberta autônoma de vulnerabilidades e defesa cibernética — posicionamento direto contra o Mythos 5.1 da Anthropic nesse nicho.

Quanto ao preço: $0,75/M input e $3,75/M output em promoção até 31 de dezembro. Após isso, dobra para $1,50/$7,50. Esse aumento programado é um sinal para quem está planejando arquitetura de custo — não construa seu FinOps usando o preço promocional como base, porque ele vai mudar. Para acesso, está disponível via Gemini API, Google AI Studio, Android Studio e Google Antigravity, além dos planos Pro e Ultra de consumidor.

📚 O que vale estudar hoje

Agentic RAG: Padrões de Reflexão e Planejamento

O RAG evoluiu além da busca por similaridade. Sistemas agentic de RAG usam reflection, planning e colaboração multi-agente para decidir dinamicamente qual estratégia de retrieval aplicar. É onde os projetos enterprise estão indo — e onde os frameworks Java já chegaram.

🔭

OpenTelemetry para GenAI e Agentes

O OpenTelemetry está sendo padronizado para semântica de GenAI — tracing de agentes não-determinísticos, rastreamento de handoffs entre agentes e controle de tokens de reasoning. Quem não instrumentar observabilidade hoje vai operar no escuro em produção.

💰

FinOps com LLMs: tokens de output e reasoning

Com os preços variando entre $0,10/M (GPT-6 Luna) e $50/M (Claude Fable 5.1 output), a seleção correta do modelo por tipo de tarefa pode reduzir custo em 10x. FinOps em LLMs exige granularidade por token de output e reasoning separados.

🔌

MCP (Model Context Protocol) no ecossistema Java

O MCP — criado pela Anthropic em novembro de 2024 e agora governado pela Linux Foundation — virou o padrão de fato para conectar agentes a ferramentas externas. Spring AI 2.0 tem suporte first-class; LangChain4j 1.17 também. Hora de integrar.

☕

Spring AI 2.0 GA — Migration Guide

A versão 2.0 GA (12 de junho de 2026) traz uma ruptura de API em relação ao 1.x. Se você tem Spring Boot 3 ainda, precisa planejar a migração para Spring Boot 4 + Spring Framework 7 antes de consumir o 2.0. O migration guide é leitura obrigatória.

🧠

LangChain4j BDI Agents + Supervisor Orchestration

A 1.17.x do LangChain4j implementa o padrão BDI (Belief-Desire-Intention) para agentes — com suspension human-in-the-loop resiliente a crashes e orquestração supervisora. É arquitetura de agente enterprise, não prototipagem.

🔇 O que pode ser ignorado por ora

Nem tudo que aparece no feed técnico merece atenção agora. Estes temas existem, mas não merecem seu tempo esta semana:

Previsões de "AGI até o final de 2026"

Voltaram com força depois dos lançamentos de setembro. São especulativas, não têm definição técnica consensual e não mudam nada no que você precisa construir hoje. Ignore o ruído e foque em arquitetura de produção.

Novos wrappers de chatbot para consumidor final

Dezenas de startups lançaram "novos assistentes de IA" aproveitando os modelos GPT-6 Luna e Gemini 3.8 Flash. Sem diferencial técnico, sem nicho de domínio definido. Nada que mude o quadro para quem está desenvolvendo soluções enterprise.

Benchmarks isolados de novos modelos sem contexto de custo

Relatórios que comparam modelos apenas por capacidade, sem considerar custo por token e latência no contexto real de uso, são métricas incompletas para decisão de arquitetura. Desconfie de qualquer ranking que não mostre $/1M tokens ao lado da performance.

☕ Radar Java + IA — Fechamento de Setembro 2026

O ecossistema Java de IA chegou a um ponto de maturidade que não existia há doze meses. Duas escolhas de framework são igualmente válidas para produção: Spring AI 2.0 GA e LangChain4j 1.17.2. A escolha certa depende do contexto — e finalmente há critérios técnicos sólidos para decidir.

Spring AI 2.0 (lançado em 12 de junho de 2026) exige Spring Boot 4 + Spring Framework 7 + Java 17 no mínimo. Traz suporte first-class ao MCP, self-correcting structured output, composable tool calling e o AgentCore SDK em GA. Se o seu time já opera com Spring Boot 4 e quer integração nativa com autoconfigure, observabilidade via Micrometer e segurança via Spring Security, essa é a escolha natural. A curva de adoção é menor para quem já é uma equipe Spring.

LangChain4j 1.17.2 (julho 2026) consolidou seu engine de workflows agentic com tipos de agentes BDI, orquestração supervisora e suspension human-in-the-loop persistida — o que significa que um agente pode ser pausado, o estado serializado, e retomado mesmo após um restart de JVM. Isso resolve um dos maiores problemas de confiabilidade em agentes de longa duração. Se MCP é central na sua arquitetura, Spring AI tem uma vantagem atual; se você precisa de agentes de workflow complexos com human-in-the-loop robusto, LangChain4j está à frente.

Abaixo, um exemplo de integração LangChain4j com MCP e Claude Fable 5.1 para um agente que analisa código-fonte de projeto Java:

// LangChain4j 1.17.x — Agente com MCP + Claude Fable 5.1
import dev.langchain4j.model.anthropic.AnthropicChatModel;
import dev.langchain4j.mcp.client.McpClient;
import dev.langchain4j.mcp.client.transport.stdio.StdioMcpTransport;
import dev.langchain4j.service.AiServices;

ChatLanguageModel model = AnthropicChatModel.builder()
    .apiKey(System.getenv("ANTHROPIC_API_KEY"))
    .modelName("claude-fable-5-1")
    .temperature(0.2)
    .build();

McpClient mcpClient = McpClient.sync(
    new StdioMcpTransport.Builder()
        .command("npx", "-y", "@modelcontextprotocol/server-filesystem",
                 "/home/user/meu-projeto-java")
        .build()
).build();

mcpClient.initialize();

interface AgenteAnaliseCodigo {
    String analisar(String instrucao);
}

AgenteAnaliseCodigo agente = AiServices.builder(AgenteAnaliseCodigo.class)
    .chatLanguageModel(model)
    .tools(McpToolProvider.from(mcpClient))
    .build();

String resultado = agente.analisar(
    "Liste os arquivos Java do projeto, identifique classes " +
    "de serviço sem injeção de dependência e sugira refatorações " +
    "alinhadas com Jakarta EE 11."
);

System.out.println(resultado);
mcpClient.close();

Um detalhe prático para quem vai começar agora: com o corte de 75% no cache de leitura do Fable 5.1, vale revisitar a implementação de Prompt Caching com LangChain4j. O framework suporta cache markers para marcar blocos de contexto fixo (system prompt, documentos de referência) que podem ser reutilizados entre chamadas. Em projetos RAG onde o contexto do sistema tem mais de 2.000 tokens — o que é praticamente todo RAG enterprise — essa otimização cobre boa parte do custo de operação.
