Spring AI 2.1.0-M1: Message Parts como fundação para agentes nativos

Em 25 de setembro, o Spring publicou o milestone Spring AI 2.1.0-M1. O headline é a introdução dos Message Parts — um novo formato de mensagem capaz de representar raciocínio intercalado com chamadas de ferramentas, texto entre imagens ou blocos específicos de provedores. Na prática, é a fundação que vai sustentar o suporte agentic nativo do Spring AI, previsto para novembro de 2026.

Junto com os Message Parts, o release inclui um OpenAiResponsesChatModel para o endpoint /v1/responses da OpenAI, com suporte a tool calling combinado com reasoning effort — o que permite construir loops de raciocínio mais controlados diretamente no ecossistema Spring. O VectorStore também ganhou melhorias: o método upsert() agora recebe um EmbeddedDocument, pareando o documento com seu vetor float[] diretamente.

Para contexto: o GA do Spring AI 2.0 foi em junho de 2026 (versão estável atual: 2.0.1). O 2.1.0-M1 é um milestone — não use em produção ainda — mas é importante acompanhar porque define a direção do framework. Quem está construindo agentes Java com Spring Boot precisa entender Message Parts agora, antes de o GA chegar.

Agentic RAG 2026: GraphRAG e Hybrid Search como padrão de produção

O panorama de RAG em produção mudou de forma substancial em 2026. O consenso que está emergindo em times de engenharia é que pure vector search é um erro arquitetural. O padrão recomendado agora é Hybrid Search — denso (embeddings) + esparso (BM25/keywords), fundidos via Reciprocal Rank Fusion — como camada base, com GraphRAG como segunda opção de recuperação para casos que exigem navegação por relacionamentos entre entidades, com o Neo4j liderando nessa frente.

O conceito de Agentic RAG marca uma virada qualitativa: em vez de um pipeline de recuperação passivo, um agente LLM controla todo o processo de busca — planejando, iterando e autocorrigindo. O LangGraph tem sido o framework de orquestração padrão para isso em produção. A memória também deixou de ser um banco de vetores acoplado à força e passou a ser uma primitiva arquitetural de primeira classe, com três tiers distintos (working, episodic e semantic memory).

Gartner: 40% dos projetos agentic serão cancelados até 2027

O Gartner publicou uma projeção que precisa entrar no radar de qualquer gestor que está autorizando projetos de IA agentic hoje: mais de 40% desses projetos serão cancelados até o final de 2027. Os três motivos principais são falta de valor claro, ausência de controle de custos e guardrails insuficientes. Não é surpresa — é o ciclo clássico de inflação de expectativas seguido de purga de projetos mal fundamentados.

O lado positivo dessa estatística é que ela já aponta o antídoto: governança de custos de LLM (FinOps para IA), definição clara de OKRs antes de construir o agente, e arquitetura de guardrails desde o dia um. Empresas com FinOps de IA maduro estão reportando custos por inferência 40 a 60% menores do que deployments não gerenciados. Ferramentas como Langfuse (observabilidade open-source) e Finout (FinOps unificado para nuvem + IA) estão se tornando parte do stack de produção.

Frameworks de orquestração de agentes sem suporte Java

Há dezenas de novos frameworks Python-first surgindo com promessas de orquestração agentic. Para o nosso contexto enterprise Java, o investimento vai para Spring AI e LangChain4j, que têm integração real com o ecossistema que já operamos.

☕ Radar Java + IA

A semana que se encerra foi movimentada para o ecossistema Java com IA. O Spring AI 2.1.0-M1 (25/09) é o item mais relevante: os Message Parts criam uma abstração capaz de representar interleaving entre raciocínio e chamadas de ferramentas dentro de uma mesma mensagem, o que é a base estrutural que faltava para agentes Spring nativos. A versão estável em produção continua sendo o Spring AI 2.0.1 (GA: junho/2026).

Para o milestone, o destaque técnico é o OpenAiResponsesChatModel para o endpoint /v1/responses da OpenAI, que combina tool calling com reasoning effort — permite que o modelo "pense" antes de executar ferramentas. Outro detalhe que passou despercebido em muito place: o VectorStore.upsert() agora aceita EmbeddedDocument, que pareia o documento com seu vetor float[] diretamente, eliminando a necessidade de reembedar na camada de aplicação. Pequeno, mas relevante para performance em pipelines de RAG de alta throughput.

No LangChain4j, o módulo agentic evoluiu com semântica de workflow real: interfaces tipadas para declarar agentes, composição em workflows sequenciais, loops, condicionais e paralelos. O padrão BDI (Belief-Desire-Intention) chega como alternativa estruturada para agentes com estado mais complexo, e a recuperação crash-resilient com human-in-the-loop suspend/resume é um diferencial importante para sistemas enterprise que precisam de auditabilidade. Comparando os dois frameworks: Spring AI 2.x é a escolha natural se você já está no ecossistema Spring Boot — integração profunda, advisor chain extensível, tooling familiar. LangChain4j é mais agnóstico a framework e tem maturado mais rapidamente no lado agentic puro.

Exemplo: Spring AI 2.1.0-M1 com OpenAiResponsesChatModel

// Spring AI 2.1.0-M1 — OpenAiResponsesChatModel com reasoning + tool calling
@Bean
public OpenAiResponsesChatModel reasoningChatModel(OpenAiApi openAiApi) {
    OpenAiResponsesChatOptions options = OpenAiResponsesChatOptions.builder()
        .model("gpt-6.1-sol")
        .reasoningEffort(ReasoningEffort.MEDIUM)
        .build();
    return new OpenAiResponsesChatModel(openAiApi, options);
}

// Invocando com tool calling integrado
@Service
public class AgentService {
    private final OpenAiResponsesChatModel chatModel;
    private final List<FunctionCallback> tools;

    public String runAgentTask(String task) {
        ChatResponse response = chatModel.call(
            new Prompt(task, OpenAiResponsesChatOptions.builder()
                .tools(tools)
                .build())
        );
        return response.getResult().getOutput().getContent();
    }
}

Ponto de atenção: o Spring AI 2.1.0-M1 é um milestone — não é estável para produção. Ideal para experimentação e antecipação do que vem em novembro. Para produção, mantenha o 2.0.1 GA.
