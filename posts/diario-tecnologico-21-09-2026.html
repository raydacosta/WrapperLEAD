Semana fechou com falha de supply-chain em quatro agentes de codificação IA. Fable 5.1 trouxe três breaking changes, OpenAI Agents API entrou em beta público e LangChain4j 1.19.0 consolida MCP e batches Anthropic.

IA Java LangChain4j Spring AI Segurança Agentes FinOps RAG

Chego neste domingo com uma semana intensa para decantar. Setembro de 2026 começou exatamente como o mercado esperava: novos modelos saindo a cada dois dias, Gartner projetando US$ 2,59 trilhões em gastos com IA ao longo do ano, e as três grandes labs — Anthropic, OpenAI e Google — operando em uma cadência que o CNBC já chama abertamente de model fatigue. Mas foi o que aconteceu na sexta-feira que dominou as conversas técnicas que acompanhei: uma vulnerabilidade de supply-chain confirmada em quatro dos principais agentes de codificação IA, incluindo o Claude Code. O Anthropic agiu rápido — versão 2.1.179 corrigiu o problema — mas a OpenAI também correu atrás no Codex, e o GitHub Copilot ainda está sem patch. Isso é exatamente o tipo de incidente que lembra que a superfície de ataque em ambientes agenticos é muito mais ampla do que estávamos tratando há seis meses.

Além da questão de segurança, dois movimentos estratégicos chamam minha atenção esta semana. O primeiro: a OpenAI abriu o Agents API para beta público no dia 10, transformando orquestração de agentes em um serviço gerenciado com parceiros como Cloudflare, DigitalOcean, Modal e Vercel. Isso muda a conta econômica de quem constrói sistemas agenticos, especialmente em contexto enterprise. O segundo: OpenAI, Anthropic e Google estão em conversas ativas para criar um órgão autorregulador ao estilo da FINRA para IA de fronteira — a proposta veio do CEO do Google DeepMind, Demis Hassabis, em julho, e os três já se sentaram mais de uma vez. Esse movimento vai moldar o que nossas equipes precisarão documentar, auditar e provar nos próximos 18 meses.

Do lado Java, o destaque técnico vai para o LangChain4j 1.19.0 — lançado em 14 de agosto, ainda muito fresco no radar da maioria das equipes — que consolida o cliente MCP na versão mais recente do protocolo (spec de 28 de julho de 2026) e entrega o AnthropicBatchChatModel. Para quem roda classificação ou extração em volume, isso resolve um gargalo de throughput de forma elegante e sem precisar implementar filas manualmente. Vou detalhar no Radar Java.

🔴 Alta Relevância

Falha de supply-chain em quatro agentes de codificação IA — Claude Code 2.1.179 corrige

Na sexta-feira, dia 18, foi confirmada uma vulnerabilidade crítica de supply-chain afetando quatro agentes de codificação amplamente utilizados. A falha permite que um ator malicioso que controle o repositório de um plugin substitua silenciosamente a versão instalada — mesmo que o plugin esteja travado em uma release revisada — por código arbitrário. O vetor de ataque passa pelo mecanismo de atualização de plugins, e o impacto potencial em ambientes corporativos é alto: imagine um plugin de banco de dados ou um conector de CI comprometido rodando dentro do seu agente de revisão de código.

O Anthropic publicou o patch em Claude Code 2.1.179 ainda no mesmo dia. A OpenAI também corrigiu no Codex 0.146.0. O GitHub Copilot ainda não tem resolução publicada — acompanhe. O Google confirmou que não vai corrigir o Gemini CLI, pois está encerrando o produto. Minha recomendação imediata: atualize o Claude Code agora, audite a lista de plugins instalados no seu ambiente, e — se você não tem uma política de allowlist de plugins — é hora de implementar uma. O vetor já existe; ignorar tem custo.

OpenAI Agents API em beta público — orquestração de agentes como serviço gerenciado

No dia 10 de setembro, a OpenAI abriu o Agents API para beta público. A proposta é direta: o mesmo harness de orquestração que roda internamente o Codex agora está disponível via API para desenvolvedores externos. Você define a tarefa, o modelo, as ferramentas e o ambiente de computação — a OpenAI gerencia o loop de orquestração, o contexto de longa duração, as chamadas paralelas de ferramentas e a colaboração multi-agente. Os parceiros de computação incluem Blaxel, Cloudflare, Daytona, DigitalOcean, E2B, Modal, Oracle, Runloop e Vercel. Precificação: taxas padrão de token mais custos de ferramenta/MCP/sandbox — sem taxa de plataforma separada.

Isso é interessante não pelo que entrega hoje, mas pelo que sinaliza: a OpenAI está se posicionando como infraestrutura de orquestração, não apenas como provedor de modelos. Para equipes que hoje gerenciam manualmente o loop agentico — retries, tool calls, compactação de contexto — a API promete reduzir substancialmente o boilerplate. Para quem usa Anthropic ou outros provedores, o movimento aumenta a pressão por paridade de features. Do ponto de vista de arquitetura enterprise: ainda prefiro ter controle sobre o loop de orquestração para auditoria e FinOps, mas o argumento de make-or-buy ficou mais complicado.

🔴 Alta Relevância

Claude Fable 5.1 e Mythos 5.1 — preços mantidos, mas três breaking changes na API

No início de setembro, o Anthropic lançou Claude Fable 5.1 e Mythos 5.1. A boa notícia: os preços de lista não subiram. Melhor ainda: o custo de leitura de cache caiu para um quarto do que era no Fable 5 — um alívio real para workloads agenticos onde cache hit é a regra, não a exceção. O Fable 5.1 está sendo posicionado como o topo para coding, knowledge work e tarefas de agente de longa duração. Paralelamente, o Anthropic cancelou o aumento de preço do Claude Sonnet 5 que estava agendado para 1º de setembro (o preço de US$ 2/US$ 10 por MTok passou a ser permanente).

A má notícia — e ela é real para quem está em produção: há três breaking changes na API entre as versões anteriores e o Fable 5.1/Mythos 5.1. Antes de fazer o upgrade, leia o guia de migração na documentação oficial. A mesma advertência vale para quem migra do Opus 4.6 para o Opus 4.7 — breaking changes documentados, guide obrigatório. O Anthropic também adicionou o header anthropic-workspace-id nas respostas e lançou em beta a compactação de conversação on-demand na Messages API. Esse último é relevante para agentes de longa duração: você envia um parâmetro compaction e recebe de volta um bloco assinado que resume mensagens anteriores, evitando overflow de contexto sem perder rastreabilidade.

OpenAI, Anthropic e Google em conversas para criar órgão autorregulador de IA ao estilo FINRA

Desde julho, os três principais labs de IA de fronteira estão em conversas regulares sobre a formação de um órgão autorregulador de padrão FINRA para IA. A proposta foi feita publicamente pelo CEO do Google DeepMind, Demis Hassabis, em 14 de julho. O foco é: avaliações de terceiros obrigatórias antes do lançamento de modelos, checagens formais de segurança e protocolos unificados de risco para ataques cibernéticos, riscos de bioarmas e comportamento enganoso. Ainda não há estatuto formal ou estrutura de governança.

O impacto prático para arquitetos e empresas que rodam IA em produção: se esse órgão se consolidar, a documentação de rastreabilidade, os registros de auditoria e os relatórios de compliance exigidos devem se alinhar a padrões formalizados — o que provavelmente se traduzirá em requisitos de observabilidade mais rígidos e logs estruturados como evidência regulatória. A California AI Transparency Act (CAITA) já está operativa desde 2 de agosto, alinhada com o Artigo 50 do EU AI Act, estabelecendo obrigações de rotulagem para sistemas com mais de 1 milhão de usuários mensais. O relógio já está correndo.

LangChain4j 1.19.0 — o que entrou e por que importa

Lançado em 14 de agosto, o 1.19.0 está entrando no radar agora para a maioria das equipes. Os itens mais relevantes:

  • MCP client atualizado para spec 2026-07-28 — a versão mais recente do protocolo. Se você tem servidores MCP em produção, valide compatibilidade antes de atualizar a lib.
  • AnthropicBatchChatModel — suporte à Anthropic Message Batches API. Para workloads de classificação, extração ou enriquecimento de dados em volume, isso troca o custo de latência por throughput. A API batch tem desconto de 50% em relação à API síncrona.
  • Milvus V2 com hybrid search — combina busca vetorial densa e esparsa em uma única query. Relevante para RAG corporativo onde cobertura de termos específicos do domínio importa.
  • watsonx.ai Model Gateway — integração para quem tem contratos IBM/watsonx no stack enterprise.
  • Google GenAI "thinking" support — acesso ao token de raciocínio explícito dos modelos Google via SDK Java.
  • Tool actions compensation — novo padrão para recuperação de erros em fluxos multi-agente. Permite que o sistema compense ações de ferramenta que falharam sem precisar reiniciar o agente inteiro.

Exemplo: AnthropicBatchChatModel em produção

// LangChain4j 1.19.0 — processamento em batch com Anthropic API
AnthropicBatchChatModel batchModel = AnthropicBatchChatModel.builder()
    .apiKey(System.getenv("ANTHROPIC_API_KEY"))
    .modelName(AnthropicChatModelName.CLAUDE_FABLE_5_1)
    .maxTokens(512)
    .build();

// Montando múltiplas requisições (até 10.000 por batch)
List<List<ChatMessage>> requests = ticketList.stream()
    .map(t -> List.of(
        SystemMessage.from("Classifique o ticket como: BUG, FEATURE, DUVIDA"),
        UserMessage.from(t.getDescription())
    ))
    .collect(Collectors.toList());

// Submissão assíncrona — processado em até 24h, 50% mais barato
BatchChatResponse batchResponse = batchModel.generate(requests);
String batchId = batchResponse.batchId();

// Posteriormente — consulta de resultado pelo batchId
List<Response<AiMessage>> results = batchModel.getResults(batchId);

Spring AI 2.0.1 — baseline novo, MCP no core

O Spring AI 2.0.0 foi a GA em 12 de junho; o 2.0.1 é o patch atual. O ponto mais importante para quem migra: requer Spring Boot 4.x e Spring Framework 7. O suporte a MCP migrou do SDK MCP Java para dentro do core do Spring AI — as anotações MCP são agora cidadãos de primeira classe. Outros destaques: tool calling unificado com progressive tool discovery, structured output auto-corretivo e integração com Azure Cosmos DB para vector search e chat memory persistente. Se você está em Spring Boot 3.x, avalie o upgrade do Spring Boot primeiro antes de saltar para o Spring AI 2.x.

Posicionamento dos frameworks em setembro de 2026

LangChain4j continua sendo a escolha para ambientes JVM políglotas (Quarkus, Helidon, Micronaut, plain Java). Spring AI é o caminho natural para quem já está all-in no ecossistema Spring. Um terceiro competidor, AgentScope Java 1.0, emergiu para orquestração multi-agente pesada, mas ainda sem adoção ampla na comunidade. O ai4jvm.com virou uma referência útil para acompanhar o ecossistema JVM+IA de forma consolidada.
