Claude Fable 5.1 — Cache 75% mais barato e Sonnet 5 com preço permanente

A Anthropic lançou o Fable 5.1 mantendo os mesmos $10 input / $50 output por milhão de tokens do Fable 5, mas com uma mudança silenciosa que muda bastante o cálculo para quem usa agentes em produção: o custo de leitura de cache caiu de $1,00 para $0,25/MTok — uma redução de 75%. A escrita de cache segue em $12,50/MTok (5 minutos) e $20/MTok (1 hora).

Além disso, a Anthropic cancelou o aumento de preço do Sonnet 5 que estava previsto para 1º de setembro: o preço de $2 input / $10 output foi confirmado como definitivo. Para quem dimensionou workloads com base na expectativa de aumento para $3/$15, isso é diretamente uma folga de orçamento.

O impacto prático é considerável: sistemas que recorrem muito a contextos longos e reutilizáveis — como agentes com system prompts extensos, documentação de domínio carregada no contexto ou conversas com histórico — vão economizar de forma imediata sem nenhuma mudança de código. Em cargas de trabalho onde cache read representa 60–70% dos tokens, essa queda de preço se traduz em redução real de custo da ordem de 30–40% no total.

Google Gemini 3.8 Flash — Terceiro Flash em seis semanas, focado em agentes e código

O Google lançou o Gemini 3.8 Flash no início de setembro, já o terceiro modelo de tier Flash em seis semanas, e desta vez com foco explícito em engenharia de software de longa duração e fluxos agênticos autônomos. O modelo alcança 90,8% no Terminal-Bench 2.1 (contra 81,6% do 3.7 Flash) e supera modelos maiores de fronteira no DeepSWE v1.1, benchmark de codificação de longa duração. Isso muda o cenário de custo-benefício para casos de uso de agentes de código.

O preço de lançamento é agressivo: $0,75 input / $3,75 output por MTok até 31 de dezembro de 2026, depois sobe para $1,50/$7,50. Existe também uma variante "Cyber" restrita a defensores governamentais, com taxa de descoberta de vulnerabilidades reais acima de 70% no CWE-Bench — o que explica por que esse lançamento veio acompanhado de um programa de acesso controlado para capacidades sensíveis.

Para mim, a sinalização mais importante aqui não é o benchmark isolado: é o Google iterando em Flash três vezes em seis semanas, cada vez com melhoras substanciais em agentes. Isso indica que o segmento de modelos de custo médio e alta capacidade agêntica está sendo travado como campo de batalha competitivo. Quem estiver avaliando seleção de modelo para sistemas de agentes precisa revisar comparações que tenham mais de 30 dias.

GPT-6 Astra — Arquitetura "Recurrent Depth" e acesso controlado para capacidades críticas

A OpenAI lançou o GPT-6 Astra em 3 de setembro com uma arquitetura nova: recurrent depth, um transformer com loops que melhora eficiência computacional mas obscurece parcialmente as cadeias de raciocínio. Treinado com mais de 100.000 GPUs no data center Stargate no Texas, o modelo tem janela de contexto de 1 milhão de tokens e capacidade de saída de 128K tokens. Preço: $10/$50 por MTok — paridade com Fable 5.1.

O detalhe que considero mais relevante do ponto de vista de segurança corporativa: a OpenAI colocou as capacidades de descoberta autônoma de vulnerabilidades atrás de um programa de acesso confiável (trusted-access program). Isso sinaliza que a fronteira entre modelos de uso geral e ferramentas de segurança ofensiva está sendo gerida de forma mais rigorosa — o que é positivo. Para quem usa LLMs em pipelines de DevSecOps, vale acompanhar esse programa.

Em termos de seleção de modelo, GPT-6 Astra e Fable 5.1 ficam na mesma faixa de preço de entrada/saída, então a decisão passa a ser técnica: latência, qualidade de raciocínio no domínio específico, e como cada um se comporta com ferramentas e function calling. Esse benchmarking precisa ser feito na carga real, não em rankings genéricos.

Mistral Agentic Search — Um concorrente direto para RAG-as-a-service

A Mistral entrou com força num mercado que estava crescendo em torno das soluções de RAG gerenciado: lançou o Agentic Search, uma camada de recuperação que permite que sistemas de IA naveguem, verifiquem e leiam documentos complexos com menos turnos, menor consumo de tokens e latência reduzida. Junto a isso, o Mistral OCR 4.1 saiu do preview e foi a GA.

O posicionamento é direto: em vez de você montar um pipeline RAG com embedding, vector store, retrieval e reranking, o Agentic Search oferece uma interface agêntica de recuperação que o modelo navega de forma autônoma. Para sistemas onde a lógica de recuperação é complexa — documentos com múltiplas seções, tabelas, referências cruzadas — isso pode ser uma simplificação arquitetural considerável. A contra-indicação é a perda de controle granular sobre cada etapa do pipeline, o que importa quando você precisa auditar resultados ou garantir compliance.

Vou testar o Agentic Search em um caso de uso interno antes de opinar sobre custo-benefício real. Por ora, marco como algo que merece avaliação técnica antes de qualquer decisão arquitetural sobre RAG em novos projetos.

Ambos agora expõem function calling de primeira classe para Anthropic, OpenAI, Google e servidores compatíveis com OpenAI. Para quem está decidindo entre os dois hoje, a questão não é mais capacidade técnica: é postura de governança e o quanto o time quer controlar o fluxo de execução do agente.

LangChain4j 1.19.0 — O split agêntico

A versão 1.19.0 do LangChain4j, lançada em 14 de agosto (a mais recente até hoje, 18 de setembro), formalizou o que já estava sendo construído nos releases 1.x: as capacidades agênticas agora vivem num módulo dedicado, langchain4j-agentic, com sub-módulos independentes para MCP (Model Context Protocol), A2A (Agent-to-Agent) e padrões agênticos comuns. Isso tem consequências diretas para o gerenciamento de dependências Maven em projetos existentes.

O ecossistema suporta hoje mais de 20 provedores de LLM e mais de 30 stores de embeddings e vector databases. Se você ainda está gerenciando integração com LLMs via chamadas HTTP diretas em Java, o custo de manutenção já justifica a migração. A documentação de release está no GitHub Releases do projeto.

// LangChain4j 1.19.0 — Dependency com módulo agêntico separado
// pom.xml

<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-agentic</artifactId>
    <version>1.19.0</version>
</dependency>

<!-- Sub-módulo MCP (Model Context Protocol) -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-mcp</artifactId>
    <version>1.19.0</version>
</dependency>

<!-- Sub-módulo A2A (Agent-to-Agent) -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-a2a</artifactId>
    <version>1.19.0</version>
</dependency>

Spring AI 2.0 — A pilha enterprise se consolida

O Spring AI 2.0 avança sobre uma base sólida: Spring Boot 4.0 / Spring Framework 7.0 / Jakarta EE 11 / Java 21 mínimo. Para quem já opera Spring em produção, a migração para Java 21 é o maior bloqueador — e precisa ser planejada antes que o Spring AI 2.0 GA chegue e você queira usar as features novas.

As capacidades mais relevantes do Spring AI 2.0 para arquiteturas RAG enterprise são:

  • Hybrid Search: combina busca semântica (vetores) com busca por palavras-chave numa única consulta — melhora significativamente a cobertura de recall em domínios técnicos com terminologia específica.
  • Hypothetical Document Embeddings (HyDE): gera um documento hipotético como intermediário de busca antes de vectorizar a query real, melhorando a precisão em queries abstratas.
  • MCP client/server support: suporte nativo ao Model Context Protocol, alinhado com a direção que a Anthropic está tomando para padronizar integração de ferramentas com modelos.
  • Actuator integration: métricas de LLM (latência, tokens, custo estimado) expostas via Spring Boot Actuator — o que fecha o loop com as práticas de observabilidade e FinOps que venho priorizando.
// Spring AI 2.0 — Pipeline RAG com HyDE e Hybrid Search
// Exemplo de configuração de ChatClient com RAG advisor

@Configuration
public class RagConfig {

    @Bean
    public QuestionAnswerAdvisor ragAdvisor(VectorStore vectorStore) {
        return QuestionAnswerAdvisor.builder(vectorStore)
            .searchRequest(
                SearchRequest.defaults()
                    .withTopK(6)
                    .withSimilarityThreshold(0.72)
                    .withFilterExpression("domain == 'contracts'")
            )
            .build();
    }

    @Bean
    public ChatClient chatClient(ChatClient.Builder builder,
                                  QuestionAnswerAdvisor ragAdvisor) {
        return builder
            .defaultAdvisors(ragAdvisor)
            .build();
    }
}
