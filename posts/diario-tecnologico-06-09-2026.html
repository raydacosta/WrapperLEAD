Claude Fable 5.1: três breaking changes que você precisa corrigir agora

A Anthropic lançou o Claude Fable 5.1 em 1º de setembro com preço inalterado — $10/M tokens de entrada e $50/M de saída — mas com uma mudança de pricing que merece atenção: o cache read caiu 75%, de $1,00 para $0,25 por milhão de tokens. Isso é um presente real para quem usa prompt caching em volume. Mas o que exige ação imediata são as três mudanças de comportamento que quebram código existente.

  • ⚡
    Forced Tool Use retorna HTTP 400. Se você tinha pipelines que forçavam uso de ferramenta via parâmetro de API, isso vai quebrar. O workaround indicado pela Anthropic é simples: instrua o modelo diretamente no prompt ("Use a ferramenta X para responder"). O Fable 5.1 segue instruções explícitas de forma confiável.
  • 🔗
    Thinking blocks são unidirecionais. Cada bloco de raciocínio agora registra o modelo que o produziu. O Fable 5.1 lê blocos de modelos anteriores, mas nenhum modelo anterior lê blocos do Fable 5.1. Se o seu sistema tem fallback para uma versão anterior do Claude, os thinking blocks são descartados — e isso pode degradar silenciosamente a qualidade das respostas.
  • ✂️
    Edição de histórico invalida thinking blocks. Qualquer alteração antes de um thinking block produzido pelo Fable 5.1 — system prompt, array de tools, mensagem anterior — invalida o bloco na próxima requisição. Esta regra se aplica a contas criadas a partir de 31 de agosto de 2026. Pipelines que modificam histórico de conversa para enxugamento de contexto precisam ser revisados.

Minha avaliação: a queda de 75% no cache read compensa financeiramente para uso intenso. Mas as três mudanças de comportamento precisam de auditoria de código antes da migração. Não trate isso como upgrade automático — trate como uma mudança de contrato de API.

Tokenomics Foundation: o FinOps de tokens virou instituição formal

A Linux Foundation anunciou o lançamento da Tokenomics Foundation, com membros fundadores que incluem Accenture, IBM, JPMorganChase, Oracle, SAP, ServiceNow e BNY. O objetivo é criar padrões abertos, benchmarks e boas práticas para a economia de IA — operando em parceria estreita com a FinOps Foundation.

O contexto que justifica a urgência: segundo dados do Goldman Sachs citados no anúncio, o volume global de tokens vai crescer 24 vezes entre 2026 e 2030, chegando a 120 quadrilhões de tokens por mês. E o custo de tokens já é o item de maior crescimento nos orçamentos de tecnologia enterprise. A FinOps X 2026 mostrou que 98% das organizações já fazem gestão de custos de IA — o que falta é padronização.

Para mim, isso confirma o que venho dizendo há meses: governança de tokens não é uma preocupação de DevOps, é uma preocupação de CFO. A criação de uma fundação dedicada indica que o mercado está maduro o suficiente para institucionalizar o tema. Se você ainda não tem uma estratégia de FinOps para LLMs, agora é o momento — tem padrão aberto a caminho.

☕ Radar Java + IA

O LangChain4j está na versão 1.10.x — resultado de uma série de releases mensais desde a estabilização da 1.0 GA em maio de 2025. O movimento mais significativo desta fase foi a formalização do módulo langchain4j-agentic, que dividiu as capacidades agenticas em sub-módulos especializados: langchain4j-agentic-mcp para integração com Model Context Protocol e langchain4j-agentic-a2a para o protocolo Agent-to-Agent.

O suporte ao protocolo A2A é o item mais relevante desta semana. O DefaultA2AClientBuilder permite conectar agentes remotos via HTTP/REST, e o McpService expõe ferramentas MCP como agentes orquestráveis. Para arquiteturas que precisam de interoperabilidade entre agentes de diferentes frameworks e linguagens, esta combinação é a base mais sólida disponível hoje no ecossistema Java.

No lado do Spring AI, o milestone 2.0.0-M2 segue em desenvolvimento sobre Spring Boot 4, com a introdução de anotações JSpecify de null-safety em toda a API. Ainda é versão milestone — não adequado para produção — mas para quem trabalha com Spring como backbone enterprise, vale acompanhar de perto. A integração entre Spring AI e LangChain4j também está mais madura em 2026, com a possibilidade de usar os dois frameworks complementarmente em vez de escolher um exclusivamente.

Um ponto de atenção prático: com as breaking changes do Fable 5.1, quem usa o langchain4j-anthropic precisa revisar a configuração de forced tool use. A propriedade que forçava uso de ferramenta via API agora retorna 400 — a correção é passar a instrução diretamente via SystemMessage ou UserMessage.

// Antes: forçar ferramenta via parâmetro — QUEBRADO no Fable 5.1
// tool_choice = { type: "tool", name: "get_weather" } → HTTP 400

// Agora: instruir via prompt — compatível com Fable 5.1
ChatLanguageModel model = AnthropicChatModel.builder()
    .apiKey(System.getenv("ANTHROPIC_API_KEY"))
    .modelName("claude-fable-5-1")
    .build();

UserMessage userMessage = UserMessage.from(
    "Use a ferramenta get_weather para verificar o clima em São Paulo."
);

// O modelo seguirá a instrução de forma confiável
Response<AiMessage> response = model.generate(userMessage);

Para A2A com LangChain4j, a configuração básica de um cliente:

// langchain4j-agentic-a2a — conectando a um agente remoto via A2A
A2AClient a2aClient = DefaultA2AClientBuilder.builder()
    .baseUrl("https://meu-agente-remoto.example.com")
    .build();

// Uso como tool dentro de um AiService
interface OrchestratorAgent {
    @Tool("Delega tarefa ao agente de análise financeira")
    String delegarAnalise(String contexto);
}
