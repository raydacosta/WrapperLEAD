🔴 Alta Relevância

Claude Fable 5.1: cache-read a $0,25 — FinOps de agentes muda de patamar

A Anthropic lançou o Fable 5.1 em 1° de setembro mantendo exatamente os mesmos preços de input e output do Fable 5 — $10 e $50 por milhão de tokens, respectivamente. A mudança que importa está no cache-read: desceu de $1,00 para $0,25 por milhão de tokens, uma redução de 75%. Para contexto: isso coloca o custo de leitura de cache em apenas 2,5% do preço normal de input, ante os 10% praticados pela maioria dos outros modelos Claude.

Para quem opera agentes com contexto longo — system prompts extensos, histórico de conversa, bases de conhecimento injetadas — o impacto é direto. A Anthropic estima redução de custo de 25% em workloads típicos e até 45% em workloads altamente agênticos. Do ponto de vista de arquitetura, isso incentiva uma estratégia que eu já defendo há meses: investir em engenharia de cache para manter o contexto quente ao invés de reenviar tokens a cada turno. Quem ainda não instrumentou sua pipeline para medir cache-hit rate precisa fazer isso agora — essa métrica virou KPI de FinOps.

Existe também o Mythos 5.1, variante restrita do mesmo modelo base, disponível para organizações de cibersegurança e ciências da vida aprovadas pela Anthropic. Não muda nada para o mercado corporativo geral, mas sinaliza que a empresa está operacionalizando camadas de acesso diferenciadas por setor regulado.

GPT-6 Astra: 1 milhão de tokens de contexto, treinamento em 100 mil GPUs e o novo topo dos benchmarks

A OpenAI liberou o GPT-6 Astra em acesso geral em 3 de setembro, após um anúncio em 1°. O modelo chega com contexto de 1.050.000 tokens, output máximo de 128K, e foi descrito pela empresa como o primeiro a acionar o seu limiar crítico de salvaguarda em cibersegurança — o que adiou o lançamento e forçou a adição de restrições ativas. Aidan Clark, VP de Pesquisa da OpenAI, confirmou que o treinamento utilizou "by far" o maior training run da empresa: mais de 100 mil GPUs no site Stargate em Texas.

Em benchmarks, o GPT-6 Astra supera tanto o GPT 5.6 Sol quanto o Claude Fable 5 em raciocínio, uso de computador, engenharia de software e trabalho científico. No plano de precificação: $10/M tokens de input e $50/M de output via API — mesmo tier do Fable 5.1, o que coloca os dois em competição direta de custo-benefício para workloads de produção. Cache de input sai a $1/M, e há modo batch a metade do preço. Para quem estava esperando para decidir entre os dois modelos frontier, esse é o momento de montar um benchmark interno real com dados do seu domínio — performance genérica já não diferencia nada a essa escala.

🟡 Média Relevância

Google ADK Kotlin 1.0 GA: paridade com Python, extensões Android e anotações @Tool

Em 9 de setembro, o Google anunciou a disponibilidade geral do ADK for Kotlin 1.0, alcançando paridade completa com o ADK Core Python enquanto adiciona uma camada mobile-first que é única na plataforma. O destaque técnico mais interessante para quem vem do mundo JVM é o sistema de anotações: ferramentas são declaradas com @Tool e @Param, e o KSP (Kotlin Symbol Processing) gera os schemas de função em tempo de compilação — eliminando a necessidade de registrar ferramentas manualmente em JSON como ocorre em abordagens mais baixo nível.

O ADK Kotlin 1.0 suporta sistemas multi-agente hierárquicos, compactação de contexto, conversas multi-turn e, especificamente para Android, agentes on-device via LiteRT-LM e ML Kit, com orquestração híbrida cloud-local via Firebase AI Logic. Para arquiteturas enterprise que precisam distribuir capacidade de agência entre borda e nuvem — um padrão que está emergindo fortemente em setores como varejo e manufatura — essa combinação é relevante. Não é para amanhã na maioria das empresas brasileiras, mas é o nível técnico que o mercado vai exigir em 12-18 meses.

"Model fatigue": labs em ritmo de release que o mercado não acompanha

A CNBC publicou uma análise sobre o fenômeno de "model fatigue" — a percepção crescente de que Meta, Google, OpenAI e Anthropic estão lançando novas versões de modelos em ritmo tão acelerado que clientes enterprise e desenvolvedores já não conseguem avaliar, migrar e testar adequadamente antes da próxima onda. Há um ponto real aqui: avaliação rigorosa de um modelo frontier exige semanas de trabalho em engenharia — comparativo de custo, testes de regressão, ajuste de prompts, validação de outputs. Ninguém está fazendo isso a cada 30 dias.

Minha leitura: o fenômeno não é exclusivamente negativo. Ele está forçando a maturidade da disciplina de LLM evaluation nas empresas — quem não tem um pipeline de evals automatizados começa a sentir a dor de não saber se vale migrar. O investimento em infraestrutura de avaliação contínua deixou de ser opcional e virou pré-requisito para qualquer time de produto que usa LLMs em produção.

📚 O que vale estudar hoje

Com base nos movimentos desta semana, estes são os temas e recursos que recomendo priorizar agora:

🧮

Engenharia de Cache de Prompts

Com o Fable 5.1 a $0,25/M em cache-read, a disciplina de prompt cache engineering virou FinOps direto. Estude como estruturar system prompts estáticos no início do contexto para maximizar cache-hit rate. A documentação da Anthropic sobre Prompt Caching é o ponto de partida.

🔧

ADK Kotlin — Anotações @Tool e @Param

Se você desenvolve em Kotlin ou Java com Spring, vale explorar o padrão de anotações do ADK Kotlin 1.0. O gerador KSP elimina boilerplate de registro de ferramentas e é conceitualmente similar ao que o Spring AI faz com @Bean tools. Repositório oficial: github.com/google/adk-kotlin.

📊

LLM Evaluation Pipelines

O cenário de "model fatigue" torna obrigatório um pipeline de evals automatizados. Estude frameworks como RAGAS para RAG, LangSmith para traces ou Braintrust para evals de LLM em produção. Sem isso, você não sabe quando (nem se) vale migrar de modelo.

🏗️

Camada de Dados em Sistemas Agênticos

Pesquisas de 2026 confirmam: a maior fonte de falha em agentes de produção é a camada de dados — não o modelo, não a orquestração. Estude padrões de indexação para RAG confiável: chunking semântico, deduplicação, freshness tracking e avaliação de relevância. A base de qualquer agente enterprise começa aqui.

🌐

Orquestração Multi-Agente com Spring AI 2.0

O Spring AI 2.0 (GA desde junho de 2026) trouxe composable tool calling e self-correcting structured output. São primitivas que simplificam muito a construção de agentes Java em ambientes Spring Boot. Vale passar pela nova documentação de Advisor chains e Tool Execution.

💡

FinOps para LLMs: métricas e KPIs

Cache-hit rate, cost-per-task, latência de first-token e custo de inferência por sessão são as métricas que começam a importar em 2026. Estude como instrumentar sua aplicação com OpenTelemetry + tracer de LLM para capturar esses dados. A redução de custo que o Fable 5.1 entrega só é mensurável se você já tem esse baseline.

☕ Radar Java + IA

O ecossistema JVM continua madurando de forma sólida. Destaco os três movimentos mais relevantes desta semana para quem constrói sistemas de IA com Java ou Kotlin:

LangChain4j 1.10.x — módulo agêntico separado

O LangChain4j está na série 1.10.x após a estabilização do 1.0 em maio de 2025. A mudança arquitetural mais importante dos últimos meses foi a separação formal das capacidades agênticas em um módulo dedicado: langchain4j-agentic, com sub-módulos para MCP, A2A (Agent-to-Agent) e padrões agênticos comuns. Essa separação é a abordagem correta: não força quem usa o framework para RAG simples a carregar dependências de orquestração que não precisa, e deixa a API de agentes evoluir de forma independente.

Spring AI 2.0 — composable tool calling em produção

O Spring AI 2.0, em GA desde junho de 2026, entregou duas features que impactam diretamente produção: self-correcting structured output — o modelo tenta reparar automaticamente a saída quando não corresponde ao schema declarado — e composable tool calling, que permite compor ferramentas em pipelines declarativos dentro de um ChatClient. Para times Java que já usam Spring Boot, a integração ficou muito mais ergonômica:

// Spring AI 2.0 — Composable Tool Calling com ChatClient
@Service
public class AnalysisAgent {

    private final ChatClient chatClient;

    public AnalysisAgent(ChatClient.Builder builder,
                         InventoryTool inventory,
                         PricingTool pricing) {
        this.chatClient = builder
            .defaultTools(inventory, pricing)
            .defaultAdvisors(new PromptCachingAdvisor())  // cache automático
            .build();
    }

    public AnalysisResult analyze(String query) {
        return chatClient.prompt()
            .user(query)
            .call()
            .entity(AnalysisResult.class);  // structured output com self-correction
    }
}

Google ADK Kotlin 1.0 — agentes JVM com anotações em tempo de compilação

Conforme detalho nos destaques, o ADK Kotlin 1.0 usa KSP para gerar schemas de ferramentas em tempo de compilação via @Tool e @Param. Para os times que trabalham com Kotlin e querem uma alternativa com suporte oficial do Google ao ecossistema JVM, essa versão 1.0 é suficientemente estável para começar projetos de produção. A paridade com Python ADK elimina o argumento de que "só dá pra fazer em Python".

No geral: Spring AI 2.0 + LangChain4j 1.10.x continuam sendo minha recomendação para novos projetos Java de IA corporativa. O ADK Kotlin entra como opção relevante para times que já usam Kotlin nativamente ou têm requisitos de on-device/Android. A escolha entre frameworks agora é menos sobre capacidade técnica e mais sobre fit com o stack e cultura do time.
