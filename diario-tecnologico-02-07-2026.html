🔥 O que chamou minha atenção hoje

🔴 Alta Relevância

Claude Fable 5 volta ao ar com salvaguardas reforçadas após bloqueio de exportação dos EUA

Em 12 de junho, o Departamento de Comércio dos Estados Unidos ordenou à Anthropic que cortasse o acesso de estrangeiros ao Claude Fable 5 e ao Mythos 5 — incluindo funcionários não-cidadãos da própria empresa. Como a Anthropic não tinha como verificar a nacionalidade de cada usuário em tempo real, a solução adotada foi desligar os dois modelos para todo mundo. O bloqueio durou quase três semanas.

Em 1º de julho, os controles de exportação foram suspensos pela administração Trump e os dois modelos voltaram ao ar. Mas a Anthropic não simplesmente religou um interruptor: a empresa publicou um framework proposto para a indústria classificar a gravidade de jailbreaks em IA, implementou um novo classificador de cibersegurança e passou a redirecionar consultas sensíveis automaticamente. O Fable 5 está disponível novamente na Claude Platform, no Claude.ai, no Claude Code e no Claude Cowork.

Minha leitura: isso não é uma vitória limpa. O episódio expôs a fragilidade de depender de modelos frontier sem uma estratégia de fallback. Na Wrapper, reforçamos há meses a importância de arquiteturas de agentes que não dependam de um único provedor ou de um único modelo. Quem ainda não tem essa discussão na mesa, precisar ter — e rápido.

Anthropic separa créditos automatizados das assinaturas — e Fable 5 muda de faixa em 7 dias

A partir de 15 de junho, a Anthropic começou a desacoplar o uso automatizado e programático das assinaturas base de seus planos. Na prática, quem usa automações — pipelines de agentes, integrações via API, ferramentas internas — passou a consumir de um pool de créditos separado, não do limite interativo da conta. Isso parece um detalhe técnico, mas tem impacto direto em custo operacional para times que rodam volumes altos.

O ponto mais crítico desta semana: após 7 de julho, o Fable 5 só ficará disponível em planos que tiverem usage credits habilitados. Organizações que não ativarem esse modelo de crédito perderão acesso ao Fable 5 completamente. Além disso, o Fast Mode para o Claude Opus 4.7 será depreciado em 24 de julho. Para o Sonnet 5, a precificação introdutória — US$ 2/M tokens de entrada e US$ 10/M tokens de saída — vale apenas até 31 de agosto; depois disso, sobe para US$ 3/US$ 15.

Minha recomendação direta: revise agora os contratos e configurações da sua organização no Claude Platform. Não é questão de se adaptar depois — em alguns casos, o acesso ao modelo que está sustentando um fluxo crítico pode ser cortado automaticamente se o billing não estiver configurado corretamente.

⚠️ Ação imediata: Acesse platform.claude.com → Settings → Billing → Habilite usage credits antes de 07/07/2026 para manter acesso ao Fable 5.

🟡 Média Relevância

Agentic RAG deixou de ser diferencial e virou baseline de produção

Um conjunto de materiais técnicos publicados esta semana — incluindo um guia enterprise de Agentic RAG para UK/EU e análises de arquiteturas do LlamaIndex — deixa claro um sinal que venho observando no mercado: o RAG híbrido não é mais vantagem competitiva, é requisito mínimo. Em 2026, empresas que ainda discutem "se vão usar RAG" estão atrasadas. A discussão passou para quando usar RAG simples, quando usar Agentic RAG e quando Graph RAG ou Multi-Agent RAG se justificam.

O que chamou minha atenção foi a maturidade das conclusões práticas: a maior parte das equipes de produção está usando orquestradores com ReAct ou Chain-of-Thought para quebrar consultas complexas, com retrieval dinâmico decidido pelo próprio modelo. Guard agents para filtro de entrada/saída viraram padrão em implantações enterprise. Complexidade adicional — como Graph RAG — só está sendo adotada quando a profundidade de raciocínio realmente exige.

EU AI Act entra em aplicação plena em 2 de agosto — o prazo é real

O AI Act da União Europeia entrou em vigor em agosto de 2024. Em 2 de agosto de 2026, a aplicação plena começa: isso inclui as obrigações para sistemas de IA de alto risco, requisitos de transparência e conformidade técnica para modelos de uso geral. Não é mais uma discussão de política — é obrigação regulatória com multas previstas.

Para quem trabalha com clientes europeus ou tem operação no continente, o impacto é concreto: sistemas que processam decisões de RH, crédito, saúde ou segurança precisam estar documentados, auditáveis e com supervisão humana comprovável. No Brasil, o PL 2.338/2023 também avança — com classificação de risco inspirada no modelo europeu. A tendência global está clara: regulação por risco, não por tecnologia.

☕ Radar Java + IA

O ecossistema Java para IA está no ponto de inflexão que eu esperava para este semestre. Não estamos mais falando de experimentação — os dois frameworks principais chegaram ao nível de maturidade que permite construir agentes em produção com confiança.

Spring AI 2.0 GA — Java 21 obrigatório, MCP no núcleo

O Spring AI 2.0 foi entregue com base no Spring Boot 4 / Spring Framework 7 / Jakarta EE 11, com Java 21 como requisito mínimo. A mudança mais relevante para quem constrói sistemas agentic: as anotações MCP foram incorporadas ao núcleo do framework, eliminando a necessidade de dependências extras. A integração com a Anthropic migrou do WebClient para o SDK oficial Java da Anthropic — quem está em produção com a implementação anterior precisa mapear as breaking changes antes de atualizar.

O suporte a JSpecify com null-safety em tempo de compilação é um ganho real para equipes grandes: erros que antes só apareciam em runtime agora são capturados no build. Pequeno detalhe, grande diferença em manutenção.

LangChain4j 1.13 — Agentes que sobrevivem a falhas

A versão 1.13.x trouxe o que eu considero a feature mais relevante para produção neste ciclo: persistência e recuperação de estado de agentes via RecoverabilityIT e PendingResponse. Em termos práticos, significa que um agente que estava no meio de uma execução complexa pode ser retomado após reinicialização do servidor — sem perda de contexto, sem reprocessamento desnecessário. Para fluxos de longa duração (análise de documentos, orquestração multi-step, pipelines batch), isso muda a arquitetura possível.

O módulo langchain4j-agentic agora está formalmente estruturado com sub-módulos para MCP, A2A e padrões agentic comuns. O suporte ao protocolo A2A chegou à versão 1.0.0.Final, o que significa que é possível construir sistemas onde agentes Java se comunicam com agentes em outras linguagens usando um protocolo padronizado — relevante para ambientes poliglotas.

// LangChain4j 1.13 — Agent com estado persistente e recuperável
@Bean
public MyAgent agentService(ChatLanguageModel model, DataSource dataSource) {
    return AiServices.builder(MyAgent.class)
        .chatLanguageModel(model)
        .chatMemoryProvider(
            memoryId -> MessageWindowChatMemory.withMaxMessages(20))
        .tools(new BusinessTools())
        // Persiste estado de execução no banco — recuperável após reinício
        .recoverabilityProvider(
            new JdbcRecoverabilityProvider(dataSource))
        .build();
}

// Spring AI 2.0 — Cliente Anthropic via SDK oficial
@Bean
public AnthropicChatModel anthropicModel() {
    return AnthropicChatModel.builder()
        .apiKey(System.getenv("ANTHROPIC_API_KEY"))
        .modelName("claude-sonnet-5-20260701")
        .maxTokens(8096)
        .build();
}

Minha avaliação para times Java

Se você está começando um projeto novo de IA hoje, Spring AI 2.0 é a escolha natural para quem já vive no ecossistema Spring — a integração com Boot é fluida e o suporte corporativo é sólido. Se você precisa de controle mais fino sobre o comportamento dos agentes, MCP nativo, A2A ou arquiteturas mais complexas, LangChain4j entrega mais flexibilidade. Os dois frameworks são complementares — e em 2026 não há mais desculpa para um time Java não ter um dos dois em produção.
